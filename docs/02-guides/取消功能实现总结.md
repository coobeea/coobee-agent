## 📋 问题诊断

### 原始问题
- 用户点击"取消"按钮后，执行没有真正停止
- 工具继续执行
- 没有中断事件发送到前端

### 根本原因
您完全正确！**两个 SDK 都支持 AbortSignal**，但我们的代码没有正确使用：

1. **@openai/agents**: 支持 `signal` 参数，但我们没有传递
2. **pi-coding-agent**: Agent 类有 `abort()` 方法，但我们没有调用

  if (controller) {
    controller.abort();  // 触发 signal.aborted

  }

## ⚠️ 已知限制

### 无法取消的场景

1. **LLM API 调用本身**
   - 即使 SDK 支持 signal，HTTP 请求可能已经发出
   - 取消会在请求完成后生效，而不是立即中断网络请求
   - 这是 HTTP 协议的限制

2. **非阻塞的异步操作**
   - 如果工具内部使用 `setTimeout` 等异步操作且未检查 signal
   - 需要每个工具自行实现取消逻辑

3. **第三方 API 调用**
   - 工具调用外部 API 时，需要传递 signal 到底层 HTTP 客户端
   - 例如 `fetch(url, { signal })`

### 取消的时机
- **最佳时机**：工具执行之间、Turn 之间
- **次佳时机**：工具执行过程中（如果工具支持）
- **无法取消**：LLM 推理的网络往返过程中
