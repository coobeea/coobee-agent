# Worker 模型密钥配置 - 反思优化

> 创建时间：2026-05-04
> 选定方案：中策

## 边界情况

- 旧配置文件可能只有 `api_key/api_url`
- 本地模型通常不需要 `api_key`
- 不同在线模型可能共用同一平台，但仍需要按模型分别存储凭证

## 安全评估

- 配置回显时必须继续脱敏
- 嵌套 `model_credentials` 里的 `api_key` 也要一起脱敏，不能只处理顶层字段

## 影响分析

- 设置页不再展示 `api_url` 输入框
- 运行时配置会逐步迁移为新结构
- 旧配置仍需可读，避免重填密钥

## 性能与可维护性

- 嵌套配置体积很小，对性能无明显影响
- 增加递归脱敏与深合并后，可维护性更好

## 优化调整

- 继续保留 `model_name` 作为当前激活模型字段，减少改动面
- 新增 `model_credentials` 作为按模型保存密钥的容器
- 服务端读取时优先读取 `model_credentials[model_name].api_key`，旧 `api_key` 作为兜底

## 最终方案

采用如下格式：

```json
{
  "model_name": "aliyun/qwen3-asr-flash-realtime",
  "model_credentials": {
    "aliyun/qwen3-asr-flash-realtime": {
      "api_key": "..."
    }
  }
}
```
