# Agent 模块 P1 阶段重构 - 需求分析

> 创建时间：2026-04-22
> 状态：进行中
> 优先级：P1（建议尽快收敛）

## 一、背景

P0 阶段已完成紧急问题修复（编译错误 + Thread 恢复路径不一致）。但代码库仍存在多处职责重叠和架构漂移问题：

- **职责不清**：多个模块维护相同的路径和上下文逻辑
- **抽象冗余**：事件链路存在两套实现，文档和代码已不一致
- **行为不统一**：两套 Runtime 的事件模型有差异
- **维护成本高**：Prompt 拼装逻辑散落在多个文件，难以追踪和优化

如不在 P1 阶段收敛这些问题，后续功能迭代会越来越困难。

## 二、问题列表

参考 `docs/architecture/agent-module-review.md`，P1 阶段需解决以下问题：

### 问题 1：Agent / Thread / Env 三层目录语义漂移

**问题描述**：

同一个 `dataDirectory` 和 `agentHomePath`，在三个地方各自维护：
- `AgentStore.create()` 创建 Agent 时初始化
- `ThreadStore.ensureAgentDataDirectory()` 创建 Thread 时补一遍
- `AgentEnvInjector` 每次执行时再推导一次

**影响**：
- 默认值改动时容易漏改，导致行为不一致
- 测试 mock 更难维护
- "路径修正"逻辑开始在多个地方出现

**关键文件**：
- `src/main/agent/agents/AgentStore.ts:184-219`
- `src/main/agent/threads/ThreadStore.ts:141-178`
- `src/main/agent/AgentEnvInjector.ts:79-104`

---

### 问题 2：流式事件链路存在两套抽象

**问题描述**：

当前真正工作的主链是：
```
Runtime yield chunk
  -> AgentExecutor.consumeAndForward()
  -> StreamEmitter.forward()
  -> EventBus
  -> EventWriter / HistoryWriter / StreamMonitor
```

但仓库里还保留着 `AgentEventWriter` 抽象，且 `AgentExecutor` 文件头仍写着"事件写入 → AgentEventWriter.ts"。

实际搜索发现，`AgentEventWriter` 只剩 Extension 场景在使用。这说明模块已经发生过架构迁移，但迁移没有完全收尾。

**影响**：
- 文档和代码不一致，新人容易误读
- 维护两套抽象增加理解成本
- 事件路径不统一，调试困难

**关键文件**：
- `src/main/agent/streaming/StreamEmitter.ts`
- `src/main/agent/streaming/consumers/EventWriter.ts`
- `src/main/agent/streaming/consumers/HistoryWriter.ts`
- `src/main/agent/AgentEventWriter.ts`
- `src/main/agent/AgentExecutor.ts` 顶部注释

---

### 问题 3：两套 Runtime 的事件模型不一致

**问题描述**：

`AgentExecutor` 的设计目标：**所有 chunk 由 Runtime yield，广播统一在 Executor 做**。

但 OpenAI Runtime 里仍有几类事件直接走了内部 `streamEmitter`：
- `agent_updated`
- 工具 `onUpdate` 产生的 `tool:delta`

PiMono 路径更接近目标架构，OpenAI 路径则保留了一部分旧做法。

**影响**：
- EventBus 和 SSE 看到的事件不一定一致
- "Runtime 只产出 chunk，Executor 才负责广播"这个约束被破坏
- 调试时需要同时追踪两条路径

**关键文件**：
- `src/main/agent/runtime/openai/OpenAIAgentRuntime.ts:606-609`
- `src/main/agent/runtime/openai/OpenAIAgentRuntime.ts:682-687`
- `src/main/agent/AgentExecutor.ts:276-311`

---

### 问题 4：Prompt 拼装链过散、过重

**问题描述**：

目前 Prompt 的来源非常分散：
- `instructions`
- `appendInstructions`
- `runtime_paths`
- `system_agents_md`
- `agent_home`
- `workspace_context`
- `skill_discovery`
- extension inject instructions
- `builder.skills(...)`

其中 PiMono 还同时做了两件事：
1. 通过 `resourceLoader.getSkills()` 传技能
2. 再把技能摘要拼进 `appendInstructions`

**影响**：
- "最终 prompt 到底长什么样"非常难推理
- 容易造成 token 浪费（技能信息双重注入）
- `AGENTS.md` 取消截断、`Agent Home` 最多注入 10000 字符，放大每轮请求成本

**关键文件**：
- `src/main/agent/AgentEnvInjector.ts:115-147`
- `src/main/agent/AgentEnvInjector.ts:313-362`
- `src/main/agent/agents/AgentHomeManager.ts:243-277`
- `src/main/agent/runtime/pimono/PiMonoAgentRuntime.ts:223-253`

---

### 问题 5：生命周期依赖只写在注释里

**问题描述**：

`ReadyAgentSystemHook` 注释里写的是 "Gateway(45) -> Agent(50) -> Config(55)"，但实际代码里：
- `ReadyGatewayHook.priority = 50`
- `ReadyAgentSystemHook.priority = 50`
- `LifecycleManager` 会把同优先级 Hook 并行执行

也就是说，**现在代码并没有真正保证 Gateway 先于 Agent System 完成**。

**影响**：
- 平时可能"碰巧没出事"，但一旦某个 Hook 变慢，就会变成初始化竞态
- 注释和代码不一致，容易误导开发者

**关键文件**：
- `src/main/lifecycle/ReadyGatewayHook.ts:17`
- `src/main/lifecycle/ReadyAgentSystemHook.ts:26`
- `src/main/common/lifecycle.ts:148-150`

---

### 遗留问题：ThreadWaker 代码重复（P0-2 遗留）

**问题描述**：

P0-2 已修复 Thread 恢复路径不一致的问题，但修复方式是"复制 ChatRoutes 的配置逻辑到 ThreadWaker"。

目前 ChatRoutes 和 ThreadWaker 各有一份约 15 行的 Builder 配置代码，存在代码重复。

**影响**：
- 任何 Builder 配置变更需要同步修改两处
- 容易出现遗漏，导致行为再次不一致

**关键文件**：
- `src/main/routes/ChatRoutes.ts:170-181`
- `src/main/agent/threads/ThreadWaker.ts:168-194`（已有 TODO 注释）

## 三、核心目标

### 主目标

**拆分职责，消除重叠，统一抽象**

具体来说：
1. **新增 `AgentContextResolver`**：统一解析运行期路径和上下文
2. **新增 `ThreadExecutionFactory`**：统一 Thread 执行的 Builder 配置
3. **新增 `PromptAssemblyService`**（可选）：统一 Prompt 拼装逻辑
4. **清理 `AgentEventWriter`**：明确唯一事件广播路径
5. **统一 Runtime 事件模型**：OpenAI Runtime 不再直接广播业务事件
6. **修正生命周期 priority**：代码和注释保持一致

### 次要目标

- 把 `injectEnv()` 缩成编排函数，不再承担所有细节
- 更新相关文档和注释，消除旧实现残留
- 为 P2 阶段（性能优化）打好基础

## 四、约束条件

1. **向后兼容**：不破坏现有功能，所有测试应继续通过
2. **渐进式重构**：优先解决影响最大的问题，不求一次性完美
3. **文档同步**：每个改动都要同步更新相关文档和注释
4. **测试覆盖**：关键路径需要有集成测试保护
