# 输入框 Ctrl 长按 AI 润色 - 方案设计

## 上策：建立通用 AI 生成基础设施

### 核心思路

建立完整的通用 AI 生成层：

- 后端新增 `ai.generate` 和 `ai.generateStream` 能力，底层使用 `ThreadlessExecutor`。
- 前端新增 `useAIGenerate` 组合式 API，统一处理状态、取消、错误、流式文本。
- 前端新增 `v-ai-generate` 指令，支持点击、快捷键、长按等触发模式。
- 前端新增轻量 `AIGenerate.vue` renderless 组件，保留旧项目 slot props 思路。
- 输入框润色只是其中一个 preset：`preset: 'polish-one-line'`。

### 优点

- 长期复用性最好，后续总结、翻译、扩写、纠错都能共用。
- 能自然吸收旧项目 renderless 组件、指令和弹层管理的优点。
- 可以给 ChatInput、AgentEditor、设置页等不同场景统一接入。

### 缺点

- 需要一次性设计较完整的 API 和事件模型。
- 如果当前只要“一句话润色”，实现成本偏高。

## 中策：先做输入框润色专用通路，再保留通用扩展口

### 核心思路

先实现一个小而稳的专用闭环：

- 后端新增 `ai.polishText` RPC：
  - 入参：`text`、`promptTemplate?`、`agentId?`、`runtimeType?`、`model?`。
  - 默认 `agentId = 'app-copilot'`。
  - 默认提示词为“一句话润色”，要求只返回润色后的文本。
  - 底层使用 `ThreadlessExecutor.run`。
- 前端新增 `useAITextPolish`：
  - 管理 `idle/pending/generating/success/error` 状态。
  - 负责调用 Gateway RPC。
  - 支持取消标记和防重复触发。
- 前端新增 `v-ai-polish` 指令：
  - 绑定到输入框或输入容器。
  - 聚焦后长按 Ctrl/Control 触发。
  - 显示小型浮层：等待触发、生成中、失败、完成。
  - 完成后回填输入框并派发 `input`/`change` 事件。

### 优点

- 实现成本适中，直接满足当前需求。
- 边界清晰，不污染现有 Chat 对话流和 chatStore。
- 后续可以把 `ai.polishText` 泛化成 `ai.generate`。

### 缺点

- 初版不是完整通用生成平台。
- 流式预览若走 RPC 返回最终文本，体验弱于旧项目；后续可补 SSE 或 Gateway 事件。

## 下策：只在某个输入组件内硬编码 Ctrl 长按润色

### 核心思路

直接在目标输入组件内监听 Ctrl 长按，调用一个后端接口回填。

### 优点

- 最快。

### 缺点

- 复用性差。
- 后续每个输入框都要重复接入。
- 不符合用户希望“通用组件/通用能力”的方向。

## 选定方案

推荐中策。先用专用 `ai.polishText` + `useAITextPolish` + `v-ai-polish` 打通“一句话润色”闭环，同时按通用生成能力的形态设计参数和状态，这样不会为了当前需求过度设计，也不会把未来扩展堵死。
