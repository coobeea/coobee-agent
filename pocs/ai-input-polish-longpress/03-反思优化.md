# 输入框 Ctrl 长按 AI 润色 - 反思优化

## 旧实现可吸收点

- Renderless 组件思路很好：AI 能力通过 slot props 暴露，不强占业务 UI。
- 指令思路很好：把生成能力绑定到任意元素，适合“输入框增强”。
- 长按 Ctrl 的等待态很好：用户按下后能看到“即将触发”的反馈，而不是黑箱等待。
- 生成中浮层预览很好：即使最终自动回填，也让用户知道系统正在处理。
- 生成完成后触发原生 `input` 事件是必要的，可以让 Vue `v-model` 同步更新。

## 旧实现不应照搬点

- 旧项目依赖 `services/ai/agents/*` 固定 agent service，不适合当前项目。
- `AiForm.vue` 强依赖 `.input` CSS 类和表单验证上下文，通用性不够。
- 旧项目对 JSON 解析和表单填充做得较重，本需求只需要纯文本润色。
- 旧项目的图标体系是 MDI，当前项目应优先使用 Carbon 图标。

## 当前项目关键约束

- 前端不能直接调用主进程 `ThreadlessExecutor`，需要通过 Gateway/RPC 或 HTTP 路由。
- 当前 `components/common/AIGenerate.vue` 的 `quickChatStream` 是占位，不能直接依赖。
- 默认 agent 应使用 `app-copilot`，默认模型由 Agent/全局配置解析。
- 润色 prompt 必须强约束“只返回润色后的文本”，避免解释性输出污染输入框。

## 交互边界

- 长按时长建议默认 800ms 到 1200ms，可配置；旧项目 2000ms 稍慢。
- Ctrl/Control 触发应只在输入框聚焦时有效。
- 生成中再次触发应忽略或取消前一次，推荐忽略并显示处理中状态。
- 空内容不触发润色，可以提示“先输入内容”。
- 结果为空或与原文一致时不破坏原输入。
- 对 `input`/`textarea` 应保留光标位置；对 `contenteditable` 和 TipTap 需要单独适配。

## Prompt 建议

默认提示词应该简短、稳定、可覆盖：

```text
请润色下面这句话，让表达更自然、清晰、简洁。保持原意、保留原语言，不要扩写成多段，不要添加解释，不要使用 Markdown，只返回润色后的句子。

原句：
{{text}}
```

可扩展变量：

- `text`：当前输入内容。
- `label`：字段标签。
- `placeholder`：输入框占位符。
- `context`：业务组件传入的额外上下文。
