# Prompt 组合结构整理 - 方案设计

> 创建时间：2026-04-23

## 上策：建立 Prompt Block Schema

- **核心思路**：为每类 prompt block 定义 schema、预算、来源和优先级，并输出结构化调试视图。
- **改动范围**：PromptAssemblyService、ContextSnapshot、Runtime 调试输出、文档。
- **优势**：长期清晰，可观测性强。
- **劣势**：实施成本较高，本轮容易扩大范围。

## 中策：收敛现有组合规则

- **核心思路**：保留现有 appendInstructions 机制，只调整确定性组合规则：去掉全局 AGENTS.md、Agent rules 独立成块、Agent Home 不再重复承载 AGENTS.md、runtime environment 精简。
- **改动范围**：PromptAssemblyService、AgentEnv、AgentHomeManager、AgentEnvInjector、测试。
- **优势**：收益明确，风险可控，不影响用户自定义文件。
- **劣势**：还没有完整 prompt block schema 和可观测面板。

## 下策：只删除全局 AGENTS.md

- **核心思路**：仅停止读取全局 `.home/agents.md`。
- **改动范围**：PromptAssemblyService。
- **优势**：最快。
- **劣势**：prompt 结构仍然凌乱，AGENTS.md 仍可能通过多个块出现。

## 方案对比

| 维度     | 上策 | 中策 | 下策 |
| -------- | ---- | ---- | ---- |
| 实施成本 | 高   | 中   | 低   |
| 长期收益 | 高   | 中高 | 低   |
| 风险     | 中   | 低   | 低   |

## 选定方案

选定中策。原因是本轮目标是收敛 prompt 组合结构，不做内容级重复检测，也不扩大到完整 schema 和调试面板。
