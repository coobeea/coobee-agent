# Prompt 组合结构整理 - 反思优化

> 创建时间：2026-04-23
> 选定方案：中策

## 边界情况

- 如果 Agent Home 中没有 `AGENTS.md`，则不注入 Agent rules 块。
- 如果 `AGENTS.md` 只有模板或注释，则跳过注入。
- 如果没有 dataDirectory，runtime environment 仍应保留 workspace / agentHome / config / skills 等基础路径。

## 安全评估

- 去掉全局 `.home/agents.md` 会减少跨 Agent 的隐式规则影响，降低全局规则误伤某个 Agent 的风险。
- 不改写用户文件，只改系统拼装规则，数据风险较低。

## 影响分析

- 所有 Agent 将不再自动继承全局 `.home/agents.md`。
- Agent 级 `AGENTS.md` 仍然生效，但通过专门的 `<agent_rules>` 块表达。
- Agent Home 注入内容将更偏向身份、记忆、偏好，不再把规则文件混在一起。

## 性能与可维护性

- runtime environment 字符数会减少，降低上下文噪音。
- PromptAssemblyService 的 block 语义更清晰，后续更容易加调试展示。

## 优化调整

- 不做 `instructions`、`SOUL.md`、`AGENTS.md` 的语义重复检测。
- 只避免系统层把同一个 `AGENTS.md` 文件通过两个固定入口注入。

## 最终方案

1. `PromptAssemblyService` 不读取全局 `.home/agents.md`，改为读取 Agent Home 下的 `AGENTS.md`。
2. block id 从 `agents_md` 收敛为 `agent_rules`。
3. `AgentHomeManager.readInjectableFiles()` 不再注入 `AGENTS.md`。
4. `formatRuntimePaths()` 输出精简版 runtime environment。
5. 更新测试验证组合顺序和全局规则不注入。
