# Agent Executor 简化调用 - 方案设计

> 创建时间：2026-04-28

## 上策：完整拆分执行生命周期

将 `AgentExecutor` 拆为执行编排、Thread 装配、生命周期、状态机、Stream 转发、Runtime 工厂等多个服务。

优点：边界最清晰，长期维护最好。

缺点：改动面较大，需要同步大量测试和文档。

## 中策：先拆入口装配和运行状态

新增：

- `ThreadExecutionFactory`：负责 `threadId + message + runtimeType` 到 `AgentExecuteRequest`。
- `SessionRunRegistry`：负责 busy、AbortController、状态查询、Thread runStatus 去重同步。

`AgentExecutor` 仍保留统一执行管道和对外方法，但不再亲自查 Thread/Agent，也不直接维护 active session 和 abort map。

优点：对外调用不变，风险较低，能立刻降低职责耦合。

缺点：Env/Extension/cleanup 仍在 Executor 内，后续还可继续拆。

## 下策：只抽一个 helper 方法

把 `streamThread` 和 `submitThread` 的重复代码抽成私有方法。

优点：最快。

缺点：没有真正解决状态管理和职责过重问题。

## 选定方案

选择中策。理由：用户强调对外必须简单，第一版应优先保持外部 API 不变，同时把最容易漂移的 Thread/Agent 装配和 run 状态管理先收敛到内部服务。
