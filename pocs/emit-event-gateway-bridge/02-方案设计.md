# emit_event 后端→前端事件链路缺失 - 方案设计

> 创建时间：2026-04-29

## 方案概述

补齐 emit_event 从 EventBus → Gateway → 前端的完整事件链路，涉及三步：
1. 在 `src/shared/events/` 中定义 AgentEvent 类型契约
2. 在后端创建 AgentEventPublisher，桥接 EventBus → Gateway
3. 在前端添加 AgentEvent 消费处理

## 详细设计

### 步骤 1：定义共享事件类型（shared 层）

**新增文件：`src/shared/events/agent.ts`**

```typescript
// ==================== Agent 事件类型 ====================

/** Agent 通过 emit_event 工具发出的前端事件类型 */
export const AgentEventTypes = {
  /** 打开预览 */
  OPEN_PREVIEW: 'agent:open-preview',
  /** 打开文件 */
  OPEN_FILE: 'agent:open-file',
  /** 通知消息 */
  NOTIFY: 'agent:notify'
} as const;

export type AgentEventType = (typeof AgentEventTypes)[keyof typeof AgentEventTypes];

/** Agent 事件 payload 类型映射 */
export interface AgentEventPayloads {
  [AgentEventTypes.OPEN_PREVIEW]: {
    url: string;
    title?: string;
  };
  [AgentEventTypes.OPEN_FILE]: {
    path: string;
  };
  [AgentEventTypes.NOTIFY]: {
    message: string;
    level?: 'info' | 'success' | 'warning' | 'error';
  };
}

/** Agent 事件的完整消息结构（包含运行时元数据） */
export interface AgentEventMessage<T extends AgentEventType = AgentEventType> {
  type: T;
  payload: AgentEventPayloads[T];
  /** 运行时元数据 */
  meta: {
    sessionId?: string;
    agentName?: string;
    timestamp: number;
  };
}
```

**修改 `src/shared/events/index.ts`**，导出新类型：

```typescript
export { AgentEventTypes } from './agent';
export type { AgentEventType, AgentEventPayloads, AgentEventMessage } from './agent';
```

### 步骤 2：修改 emit_event 工具，使用类型化事件发射

**当前代码**（`emit-event.ts:69`）：
```typescript
eventBus.emit('agent:event', enrichedPayload);
```

**修改为**：emit_event 工具负责将 LLM 传入的 `{ event, payload }` 映射为 `AgentEventMessage`，然后 emit 到 EventBus。

事件名改为使用枚举常量，按事件类型拆分发射：

```typescript
// 根据 event 类型构建对应的 AgentEventMessage
const agentEvent: AgentEventMessage = {
  type: event as AgentEventType,  // 如 'agent:open-preview'
  payload: payload as AgentEventPayloads[AgentEventType],
  meta: {
    sessionId: context?.sessionId,
    agentName: context?.agentName,
    timestamp: Date.now()
  }
};

// 直接按事件类型发射（便于 Publisher 按类型过滤）
eventBus.emit(event as AgentEventType, agentEvent);
```

### 步骤 3：创建 AgentEventPublisher

**新增文件：`src/main/publishers/AgentEventPublisher.ts`**

参考现有 `StreamPublisher.ts` 和 `ThreadPublisher.ts` 的模式：

```typescript
import { eventBus } from '@main/common/eventbus';
import { gateway } from '@main/common/gateway';
import { AgentEventTypes } from '@shared/events/agent';
import type { AgentEventMessage } from '@shared/events/agent';

/**
 * 监听 EventBus 上的 Agent 事件，通过 Gateway WebSocket 广播到前端。
 *
 * 该模块作为 Publisher 被 Gateway 自动扫描加载（与其他 Publisher 模式一致）。
 */
export function registerPublisher(): () => void {
  const cleanups: (() => void)[] = [];

  const eventMap = {
    [AgentEventTypes.OPEN_PREVIEW]: AgentEventTypes.OPEN_PREVIEW,
    [AgentEventTypes.OPEN_FILE]: AgentEventTypes.OPEN_FILE,
    [AgentEventTypes.NOTIFY]: AgentEventTypes.NOTIFY
  };

  for (const eventType of Object.values(eventMap)) {
    const handler = (msg: AgentEventMessage) => {
      gateway.broadcastEvent(eventType, msg);
    };
    eventBus.on(eventType, handler);
    cleanups.push(() => eventBus.off(eventType, handler));
  }

  return () => cleanups.forEach((fn) => fn());
}
```

**修改 `src/main/publishers/AgentEventPublisher.ts` 的注册**：

如果 Publisher 使用自动扫描机制（目录扫描），只需要把文件放在 `src/main/publishers/` 下即可。如果不是，需要在 Gateway 初始化时注册。

### 步骤 4：前端消费 Agent 事件

**修改 `src/renderer/src/` 下的相关文件**：

使用 `useGateway` composable 监听 agent 事件：

```typescript
// 在合适的 setup 位置（如 gatewaySetup 插件中）

// 监听 open-preview

// 监听 open-file
```

## 不涉及范围

- **不改变 `emit_event` 工具的外部接口**：LLM 看到的函数签名（event + payload）保持不变
- **不改变 Gateway 核心架构**：只是新增一个 Publisher，不修改 Gateway 本身
- **不改变 EventBus 机制**：继续使用现有 EventBus（mitt）

## 事件流（修改后）

```
emit_event 工具
  │ 构建 AgentEventMessage（含 meta）
  │
  └─► eventBus.emit('agent:open-preview', msg)
        │
        └─► AgentEventPublisher 监听到事件
              │
              └─► gateway.broadcastEvent('agent:open-preview', msg)
                    │
                    └─► WebSocket → 前端 Gateway Client
                          │
                          └─► useGateway.on('agent:open-preview', handler)
                                │
                                └─► UI 响应：打开预览 / 打开文件 / 弹出通知
```

## 风险评估

- **低风险**：新增代码，不修改现有逻辑
- Publisher 模式已有 StreamPublisher / ThreadPublisher 先例，方案成熟
- 共享类型定义在 `src/shared/events/` 中，与现有体系一致
- 前端 handler 需要具体 UI 实现（预览面板、文件打开、通知组件），这些 UI 组件可能需要额外开发
