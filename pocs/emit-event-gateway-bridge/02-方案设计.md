# emit_event 后端到前端事件链路缺失 - 方案设计

> 创建时间：2026-04-29
> 最近更新：2026-04-29

## 设计原则

1. **外层通道稳定**：Gateway 只新增一个 `agent:message`。
2. **内部 action 扩展**：具体能力通过 `message.action` 分发。
3. **payload 统一**：所有 action 都使用 `{ text?: string; data?: Record<string, unknown> }`。
4. **外部使用简单**：Agent/LLM 不理解 Gateway，只填写 action 和统一 payload。
5. **运行时校验**：payload 统一后，按 action 做必要字段校验。
6. **贴合现有架构**：后端走 Publisher 自动扫描；前端走 `gatewaySetup -> eventBus -> event_handles`。

## 上策：Agent UI Action 子系统

- **核心思路**：
  - 建立可注册的 Agent UI Action 系统。
  - 每个 action 有 manifest、权限、安全策略、payload schema、handler。
- **改动范围**：
  - shared events
  - action registry
  - tool
  - Gateway Publisher
  - renderer action handler registry
- **优势**：
  - 长期扩展能力最好。
  - 可以支持插件化 UI action。
- **劣势**：
  - 当前需求只需要三个 action，上策明显偏重。
  - 会让 `emit_event` 从轻量通知工具变成一套 action 平台。

## 中策：固定 `agent:message` + 统一 payload（推荐）

- **核心思路**：
  - Gateway 顶层只新增 `agent:message`。
  - Message 内部字段固定为 `type/action/payload/meta/timestamp`。
  - `payload` 永远只有 `text` 和 `data` 两个字段。
  - 当前只执行 `notify`、`open-preview`、`open-file` 三个 action。
  - 后续新增 action 时，优先只改 action 文档和 handler，不改 Gateway 通道结构。
- **改动范围**：
  - `src/shared/events/agent.ts`
  - `src/shared/events/gateway.ts`
  - `src/shared/events/frontend.ts`
  - `src/shared/events/index.ts`
  - `src/main/agent/tools/builtin/emit-event.ts`
  - `src/main/publishers/AgentMessagePublisher.ts`
  - `src/renderer/src/plugins/gatewaySetup.ts`
  - `src/renderer/src/eventbus/event_handles/agentEventsHandle.ts`
  - `src/renderer/src/plugins/eventbusSetup.ts`
  - 测试文件
- **优势**：
  - 外层协议稳定，不会随着 action 增长而臃肿。
  - payload 描述统一，后续写工具描述和文档更简单。
  - 复用现有 Gateway 和前端事件分层。
  - 当前功能能完整落地。
- **劣势**：
  - 单个 action 的 payload TypeScript 静态约束较弱。
  - 必须认真做运行时校验。

## 下策：最小桥接 `agent:event`

- **核心思路**：
  - 保留 `eventBus.emit('agent:event', enrichedPayload)`。
  - 新增 Publisher 直接转发 `agent:event`。
  - 前端在一个 handler 里按 `_event` 分发。
- **改动范围**：
  - `src/main/publishers/AgentEventPublisher.ts`
  - `src/renderer/src/plugins/gatewaySetup.ts`
  - 一个前端消费 handler
- **优势**：
  - 改动最小。
  - 能较快验证链路。
- **劣势**：
  - `_event`、`_sessionId` 等内部字段继续混在 payload 中。
  - shared 类型契约仍然弱。
  - 未来扩展容易继续分叉。

## 选定方案

选定 **中策：固定 `agent:message` + 统一 payload**。

理由：

- 用户明确希望外层事件固定，不希望 `agent:*` 顶层事件随着能力增加而越来越多。
- payload 统一为两个字段后，工具描述和后续 action 扩展都更稳定。
- 运行时校验可以弥补统一 payload 带来的静态类型弱化。
- 方案仍然贴合现有 Gateway Publisher 自动扫描与前端 EventBus handler 模式。

## 详细设计

### 1. shared 层：定义 Agent Message 契约

新增 `src/shared/events/agent.ts`。

建议结构：

```ts
export const AgentEventTypes = {
  MESSAGE: 'agent:message'
} as const;

export const BuiltinAgentMessageActions = {
  NOTIFY: 'notify',
  OPEN_PREVIEW: 'open-preview',
  OPEN_FILE: 'open-file'
} as const;

export type BuiltinAgentMessageAction = (typeof BuiltinAgentMessageActions)[keyof typeof BuiltinAgentMessageActions];

export type AgentMessageAction = BuiltinAgentMessageAction | (string & {});

export interface AgentMessagePayload {
  /** 给用户看的主要文本，例如通知文案、预览标题、文件说明 */
  text?: string;
  /** 给程序执行用的结构化参数，例如 url/path/level */
  data?: Record<string, unknown>;
}

export interface AgentMessageMeta {
  sessionId?: string;
  agentName?: string;
}

export interface AgentMessage {
  type: typeof AgentEventTypes.MESSAGE;
  action: AgentMessageAction;
  payload: AgentMessagePayload;
  meta: AgentMessageMeta;
  timestamp: number;
}
```

同时提供运行时辅助函数：

- `normalizeAgentMessage(action: string, payload: unknown, meta: AgentMessageMeta): AgentMessage | { error: string }`
- `isBuiltinAgentMessageAction(action: string): action is BuiltinAgentMessageAction`

当前运行时只允许三种内置 action：

| action         | 校验规则                                                  |
| -------------- | --------------------------------------------------------- |
| `notify`       | `payload.text` 必须是非空字符串；`data.level` 可选        |
| `open-preview` | `payload.data.url` 必须是非空字符串；`payload.text` 可选  |
| `open-file`    | `payload.data.path` 必须是非空字符串；`payload.text` 可选 |

`data.level` 允许值：

- `info`
- `success`
- `warning`
- `error`

缺省为 `info`。

### 2. shared gateway/frontend 类型：只新增一个 Agent Message 通道

修改 `src/shared/events/gateway.ts`：

- `GatewayEventTypes` 增加：
  - `AGENT_MESSAGE: AgentEventTypes.MESSAGE`
- `GatewayEventPayloads` 增加：
  - `[GatewayEventTypes.AGENT_MESSAGE]: AgentMessage`

修改 `src/shared/events/frontend.ts`：

- `FrontendEventPayloads = IpcEventPayloads & GatewayEventPayloads` 会自然包含 `agent:message`

修改 `src/shared/events/index.ts`：

- 导出 `AgentEventTypes`
- 导出 `BuiltinAgentMessageActions`
- 导出 `AgentMessage`、`AgentMessagePayload`、`AgentMessageMeta`、helper 函数

### 3. 工具层：保持 `emit_event` 简单，但发射 AgentMessage

修改 `src/main/agent/tools/builtin/emit-event.ts`：

- 工具参数可以继续保持：
  - `event: string`
  - `payload?: { text?: string; data?: Record<string, unknown> }`
- 其中 `event` 在内部语义上就是 `action`
- 工具描述中明确 payload 只有两个字段：
  - `text`: human-readable text
  - `data`: structured action parameters
- 执行时调用 `normalizeAgentMessage(event, payload, meta)`
- 如果返回错误：
  - `success: false`
  - `llmContent` 告诉 Agent 当前支持的 action 和 payload 格式
- 如果成功：
  - `eventBus.emit(AgentEventTypes.MESSAGE, message)`
  - `metadata` 中记录 action 和 payload

关键点：

- 不再发射 `agent:event`
- 不再把 `_event/_sessionId/_agentName/_timestamp` 混入 payload
- 不新增多个顶层 `agent:*` Gateway 事件
- 不允许未知 action 静默成功

### 4. Publisher：只转发 `agent:message`

新增 `src/main/publishers/AgentMessagePublisher.ts`：

```ts
import { AgentEventTypes } from '@shared/events/agent';

export default [AgentEventTypes.MESSAGE];
```

原因：

- `Gateway.discoverEventPublishers()` 已支持 `export default string[]`
- 数组 Publisher 会自动 `eventBus.on(eventName)` 并 `broadcastEvent(eventName, data)`
- 固定一个事件通道，后续 action 扩展无需改 Publisher

### 5. 前端 Gateway 桥接：只桥接 `agent:message`

修改 `src/renderer/src/plugins/gatewaySetup.ts`：

- 抽出 `bridgeGatewayEvent(eventType)`
- 桥接已有：
  - `stream:message`
  - `thread:message`
- 新增桥接：
  - `GatewayEventTypes.AGENT_MESSAGE`

本层只负责转发，不执行业务 UI。

### 6. 前端消费：agentEventsHandle 按 action 分发

新增 `src/renderer/src/eventbus/event_handles/agentEventsHandle.ts`。

职责：

- 监听 `AgentEventTypes.MESSAGE`
- 根据 `message.action` 分发：
  - `notify`
    - `text` 作为通知文案
    - `data.level` 决定 toast 类型，缺省 `info`
  - `open-preview`
    - `data.url` 作为 URL
    - `text` 作为标题
    - 调用 `useOpenFiles().openUrl(url, text)`
  - `open-file`
    - `data.path` 作为文件路径
    - 调用 `useOpenFiles().openFile(path)`
- 未知 action：
  - 记录 warning
  - 可选 toast 提示，不阻塞应用

修改 `src/renderer/src/plugins/eventbusSetup.ts`：

- 注册 `setupAgentEvents()`

## 不涉及范围

- 不设计通用自定义 UI action 市场。
- 不做多窗口定向推送。
- 不改变 Gateway 核心协议。
- 不把 payload 扩展为每个 action 一套类型。
- 不改变 Agent/LLM 的使用复杂度。
