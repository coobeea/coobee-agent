# P2 - 性能与稳定性优化：反思优化

## 1. 边界条件处理

### P2-1: 异步 IO 边界条件

#### 队列溢出
**场景**：事件产生速度超过磁盘写入速度  
**处理**：
- 设置队列上限（如 1000 条）
- 超过上限时采取策略：
  - **丢弃**：丢弃最旧的事件（记录 warning）
  - **背压**：暂停事件生成（可能影响 Agent 执行）
  - **降级**：切换到同步写入（保证不丢失）

**推荐**：**丢弃** + warning 日志（事件流本身允许部分丢失）

#### 应用崩溃
**场景**：应用异常退出时，队列中的事件尚未写入  
**处理**：
- 在 `before-quit` Hook 中强制 `flush()` 所有队列
- 设置超时（如 5s），避免退出卡死
- 记录未写入事件数，供下次启动时恢复（可选）

#### 并发写入
**场景**：多个 Agent 同时执行，多个队列并发 flush  
**处理**：
- 每个 session 独立队列，互不影响
- 使用 `fs.promises.appendFile`（Node.js 会处理文件锁）
- 测试验证：并发 10+ session 写入无数据损坏

### P2-2: CoreSkills 清理边界条件

#### 隐式依赖检查
**场景**：某些 Extension 或测试仍在使用 CoreSkills  
**处理**：
- 全局搜索 `import.*CoreSkills`
- 搜索 `CoreSkills.get` 等调用
- 如有依赖，提供迁移指引或临时保留

#### 子 Agent 兼容性
**场景**：子 Agent 配置中引用了 CoreSkills  
**处理**：
- 检查所有 Agent 定义文件（`.json`）
- 如有引用，更新为显式 Skill 路径
- 提供数据迁移脚本（可选）

### P2-3: Skill 缓存失效边界条件

#### 高频失效
**场景**：Extension watch 频繁触发，导致缓存失效过于频繁  
**处理**：
- 增加防抖（debounce）：300ms 内多次变更只失效一次
- 监控缓存命中率，确保不低于 80%

#### 部分失效
**场景**：只有部分 Skill 更新，但全局失效浪费性能  
**处理**：
- 提供 `invalidateCache(skillPath?: string)` 精确失效接口
- Extension watch 时传入具体路径
- 缓存键设计支持路径粒度

## 2. 安全性分析

### P2-1: 异步 IO 安全性

#### 数据一致性
- **风险**：异步写入可能导致事件顺序错乱
- **缓解**：
  - 队列严格 FIFO
  - 单个 session 的事件串行 flush
  - 测试验证：事件顺序与生成顺序一致

#### 路径遍历
- **风险**：无（已有路径验证在 `AgentContextResolver`）
- **缓解**：复用现有路径验证逻辑

### P2-2: CoreSkills 清理安全性

- **风险**：极低（纯删除操作）
- **缓解**：充分的回归测试

### P2-3: Skill 缓存失效安全性

- **风险**：缓存失效后重新加载 Skill 可能抛出异常
- **缓解**：
  - `SkillManager.loadSkills()` 已有异常处理
  - 失效后首次加载失败，记录 error，不影响系统运行

## 3. 错误处理原则

### 异步 IO 错误处理
```typescript
async flush(): Promise<void> {
  try {
    await fs.promises.appendFile(this.filePath, this.serialize(this.queue));
    this.queue = [];
  } catch (err) {
    log.error(`[EventWriter] Failed to flush events: ${err}`);
    
    // 降级策略：如果连续失败 3 次，切换到同步写入
    this.failureCount++;
    if (this.failureCount >= 3) {
      log.warn('[EventWriter] Too many failures, falling back to sync mode');
      this.syncMode = true;
    }
  }
}
```

### 缓存失效错误处理
```typescript
invalidateCache(): void {
  try {
    this.cache.clear();
    log.debug('[SkillManager] Cache invalidated');
  } catch (err) {
    log.error('[SkillManager] Failed to invalidate cache:', err);
    // 不抛出，允许系统继续运行
  }
}
```

## 4. 性能优化分析

### P2-1: 异步 IO 性能

#### 预期提升
- **同步写入**：每次 `appendFileSync` 约 1-5ms（取决于磁盘）
- **异步批量**：10 个事件合并写入，理论提升 5-10x
- **高频场景**（100 events/s）：主线程阻塞从 100-500ms → 10-50ms

#### 性能测试
```typescript
// 压力测试：模拟 100 events/s 持续 10s
async function stressTest() {
  const writer = new AsyncEventWriter('/tmp/test.jsonl');
  const start = performance.now();
  
  for (let i = 0; i < 1000; i++) {
    await writer.write({ type: 'text:delta', text: 'test' });
    if (i % 100 === 0) await Await(10); // 模拟间隔
  }
  
  await writer.flush();
  const elapsed = performance.now() - start;
  
  console.log(`写入 1000 事件耗时: ${elapsed}ms`);
  // 预期：<200ms（异步），>1000ms（同步）
}
```

### P2-3: Skill 缓存性能

#### 失效开销
- 缓存失效本身：O(1)（`Map.clear()`）
- 首次重新加载：O(N)（N 为 Skill 文件数）
- 防抖后频率：<1 次/300ms（可接受）

#### 监控指标
```typescript
class SkillManager {
  private cacheHits = 0;
  private cacheMisses = 0;
  
  getCacheStats(): { hitRate: number } {
    const total = this.cacheHits + this.cacheMisses;
    return { hitRate: total > 0 ? this.cacheHits / total : 0 };
  }
}

// 预期命中率：> 80%（热重载场景）
```

## 9. 优化调整

### 基于反思的方案调整

#### 调整 1：队列上限设置为可配置
**原因**：不同部署环境磁盘性能差异大  
**调整**：通过环境变量 `EVENT_QUEUE_MAX_SIZE` 配置（默认 1000）

#### 调整 2：CoreSkills 移至 legacy/ 而非删除
**原因**：可能有第三方 Extension 依赖  
**调整**：
- 移至 `src/main/agent/skills/legacy/CoreSkills.ts`
- 标记 `@deprecated`
- 提供 3 个月的迁移期

#### 调整 3：Skill 缓存失效增加防抖
**原因**：watch 可能频繁触发  
**调整**：
- 使用 `lodash.debounce` 或手写防抖
- 延迟 300ms（可配置）
