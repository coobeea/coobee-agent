# P2 - 性能与稳定性优化：需求分析

## 1. 问题背景

P2 级别的问题虽然不会导致编译错误或功能失效，但会影响系统的性能、稳定性和可维护性。这些问题需要在架构层面进行优化，以提升系统的健壮性。

## 2. 核心问题

### P2-1: 主进程同步文件 IO 过多

**问题描述**：  
当前大量路径使用了同步 IO 操作（`readFileSync`, `writeFileSync`, `appendFileSync`, `mkdirSync`），这些代码都跑在 Electron 主进程里。主进程同时还承担窗口生命周期、IPC、Gateway、EventBus 等职责。

**关键文件**：
- `src/main/agent/threads/ThreadStore.ts`
- `src/main/agent/agents/AgentStore.ts`
- `src/main/agent/streaming/consumers/EventWriter.ts`
- `src/main/agent/streaming/consumers/HistoryWriter.ts`

**影响**：
- 高频 `text:delta`、工具输出、批量 Thread 列表读取场景下，同步 IO 会放大主线程阻塞风险
- 可能导致 UI 卡顿、IPC 响应延迟
- 影响用户体验，特别是在大量 Agent 会话时

### P2-2: CoreSkills 旧机制残留

**问题描述**：  
架构文档已明确"强制注入核心 Skills 已废弃"，但代码层面 `CoreSkills.ts` 仍在导出和测试中，让后来维护者误以为"系统其实还有一层隐式核心技能机制"。

**关键文件**：
- `src/main/agent/skills/CoreSkills.ts`
- `src/main/agent/skills/index.ts`
- `src/main/agent/skills/__tests__/CoreSkills.test.ts`

**影响**：
- 代码和文档不一致，增加理解成本
- 测试仍在验证已废弃的机制
- 可能导致未来引入错误的依赖假设

### P2-3: Skill 缓存与热重载联动缺失

**问题描述**：  
`SkillManager` 有 30 秒全局缓存，但当前代码里几乎没有看到扩展加载/卸载后主动 `invalidateCache()` 的路径。

**关键文件**：
- `src/main/agent/skills/SkillManager.ts:134-143`
- `src/main/agent/skills/SkillManager.ts:179-180`
- `src/main/agent/extension/ExtensionLoader.ts`

**影响**：
- 新 Skill 目录刚装载时，短时间内可能仍然读到旧缓存
- 热插拔后的行为不够可预期
- 开发时需要重启应用才能看到 Skill 更新

## 3. 目标定义

### 核心目标
1. **降低主线程阻塞风险**：将同步 IO 操作迁移到异步版本或 Worker
2. **代码与文档一致**：清理已废弃的 CoreSkills 机制
3. **提升热重载可靠性**：建立 Skill 缓存与扩展装卸的明确联动

### 次要目标
- 提升系统整体性能
- 减少技术债务
- 提升开发体验（热重载更可靠）

## 4. 约束条件

### 技术约束
- Electron 主进程架构不变
- 不能破坏现有的 Extension 机制
- 异步改造需要保持 API 兼容性（或提供迁移路径）

### 业务约束
- 不能影响现有 Agent 的执行行为
- 不能破坏已有的 Thread/Agent 数据
- 改动需要向后兼容（或提供数据迁移）

### 团队约束
- P2 任务优先级低于 P0/P1
- 可以分阶段实施
- 每个阶段需要有独立的测试验证

## 5. 风险评估

### P2-1 风险（同步 IO）
- **高**：异步改造可能引入 race condition
- **高**：需要全面回归测试（特别是并发场景）
- **中**：Worker 方案需要额外的序列化开销

### P2-2 风险（CoreSkills）
- **低**：纯删除操作，风险可控
- **中**：需要确认没有隐式依赖

### P2-3 风险（Skill 缓存）
- **低**：增加失效逻辑，风险较小
- **中**：需要验证缓存失效不会影响性能

## 6. 范围界定

### 包含
- 事件写盘异步化（P2-1）
- ThreadStore/AgentStore 异步化（P2-1，可选）
- CoreSkills 移除或重命名（P2-2）
- Skill 缓存失效机制（P2-3）

### 不包含
- Worker 完整改造（P2-1，留作可选优化）
- 其他模块的同步 IO 改造（超出 Agent 模块范围）
- 缓存策略的全面重新设计

## 7. 验收标准

### P2-1 验收标准
- ✅ EventWriter/HistoryWriter 改为异步写入
- ✅ 提供内存队列 + 批量 flush 机制
- ✅ 高频写入场景（>100 events/s）主线程无明显阻塞
- ✅ 所有相关测试通过

### P2-2 验收标准
- ✅ CoreSkills.ts 移至 legacy/ 或完全删除
- ✅ 相关导出和测试清理
- ✅ 文档更新，明确 Skill 机制现状

### P2-3 验收标准
- ✅ Extension load/unload/watch 后主动失效缓存
- ✅ 热重载场景测试通过（修改 Skill 后立即生效）
- ✅ 性能无明显退化

## 8. 后续计划

P2 优化完成后，可以考虑：
- 监控主线程占用率，识别其他性能瓶颈
- 评估是否需要引入更激进的 Worker 方案
- 建立性能基准测试，持续跟踪优化效果
