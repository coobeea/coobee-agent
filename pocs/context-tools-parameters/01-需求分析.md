# context.jsonl 工具参数 Schema 缺失 - 需求分析

> 创建时间：2026-04-28

## 需求背景

查看 `.home/workspaces/307549385198301184/context.jsonl` 时发现，`config.tools` 和 `rawApiRequest.tools` 中记录的工具定义只有 `name` 和 `description`，完全没有 `parameters`（参数 JSON Schema）。这意味着 context.jsonl 作为执行审计快照，无法还原工具调用时模型接收到的完整参数规格。

## 核心问题

问题出在**两处**代码，都是故意"简化存储"导致：

**位置 1：`AbstractAgentRuntime.writeSnapshot()`**

文件：`src/main/agent/runtime/AbstractAgentRuntime.ts:170-172`

```typescript
tools: options.tools.map((t) => ({ name: t.name, description: t.description }));
```

只映射了 `name` 和 `description`，丢弃了 `parameters`（Zod Schema）。导致 `config.tools` 缺少参数定义。

**位置 2：`PiMonoAgentRuntime.buildRequestPreview()`**

文件：`src/main/agent/runtime/pimono/PiMonoAgentRuntime.ts:513-520`

```typescript
// 注：parameters 是 Zod Schema，这里简化存储为工具名称列表
const tools = options.tools?.map((t) => ({
  type: 'function',
  function: {
    name: t.name,
    description: t.description
  }
}));
```

注释明确写了"简化存储为工具名称列表"。导致 `rawApiRequest.tools` 也缺少参数定义。

## 影响范围

**不影响 LLM 实际调用**：`PiMonoToolConverter` 和 `OpenAIAgentRuntime.convertTools()` 都会正确地将 Zod Schema 转换为 JSON Schema 传给模型。工具调用本身是正常的。

**影响审计和调试**：

- context.jsonl 无法完整还原当时的执行上下文
- 排查工具调用问题时，看不到模型实际收到了怎样的参数约束
- 如果参数 schema 有误导致模型调用异常，context.jsonl 无法提供线索

**影响面**：所有 Runtime 类型（pi-mono / openai / claude）都会经过 `writeSnapshot()`，因此 `config.tools` 在所有 Runtime 下都缺少参数。

## 相关文件

- `src/main/agent/runtime/AbstractAgentRuntime.ts` — `writeSnapshot()` 快照写入
- `src/main/agent/runtime/pimono/PiMonoAgentRuntime.ts` — `buildRequestPreview()` 请求预览
- `src/main/agent/runtime/claude/ClaudeAgentRuntime.ts` — 可能有同样问题
- `src/main/agent/tools/types.ts` — `ToolDefinition` 类型定义（包含 `parameters` 字段）
- `src/main/agent/runtime/pimono/PiMonoToolConverter.ts` — 实际转换（正确使用 `z.toJSONSchema()`）
