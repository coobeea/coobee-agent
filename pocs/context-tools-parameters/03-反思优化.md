# context.jsonl 工具参数 Schema 缺失 - 反思优化

> 创建时间：2026-04-28

## 设计反思

### 1. 为什么参数被"简化存储"？

原始注释写的是"parameters 是 Zod Schema，这里简化存储为工具名称列表"。推测原因：

- Zod Schema 是 JavaScript 对象，不能直接 JSON.stringify（包含函数引用等）
- 当时可能不知道 Zod 提供了 `toJSONSchema()` 方法
- 开发时优先完成了核心功能，快照完整性作为"锦上添花"被搁置

### 2. `stripSchemaRef` 是否应该提取为共享函数？

目前 `stripSchemaRef` 是 `PiMonoToolConverter.ts` 中的私有函数。如果 `AbstractAgentRuntime` 和 `PiMonoAgentRuntime` 都要使用，应该提取到共享位置。建议放到：

- `src/main/agent/runtime/shared/zod-utils.ts` 或
- 直接在 `AbstractAgentRuntime` 中内联（因为只是去掉一个 `$schema` 字段，一行代码）

### 3. 是否需要担心 JSONL 文件膨胀？

12 个工具的参数 schema 合计约 2-5 KB。对于一个典型的 context.jsonl（已有几十 KB），增长在可接受范围内。权衡审计完整性 vs 文件体积，审计完整性更重要。

### 4. OpenAI Runtime 的 rawApiRequest 来源不同

`OpenAIAgentRuntime` 目前没有实现 `buildRequestPreview()`，`rawApiRequest` 可能来自 OpenAI SDK 的实际请求对象。如果 SDK 原生返回完整的 tool definitions（含 parameters），那 OpenAI Runtime 可能不存在此问题。需要进一步验证。

### 5. 后续改进方向

- 考虑在 context.jsonl 中区分 `config.tools`（配置级别的工具列表）和实际 `rawApiRequest.tools`（API 请求级别的工具定义）
- 如果两者内容重复，可考虑只在 `rawApiRequest.tools` 中保留完整参数，`config.tools` 保持精简
- 或者反过来：`config.tools` 记录完整定义，`rawApiRequest.tools` 依赖 `config.tools` 不再重复
