# ASR 语音对话输入区 - 方案设计

> 创建时间：2026-04-29

## 上策：抽象完整 Voice Runtime Composable

将 ASR WebSocket、麦克风采集、TTS 播放、状态管理抽成 `useVoiceConversation()`，输入区组件只负责展示。

- 优点：长期复用性最好，能统一旧 `VoicePanel` 和新输入区逻辑。
- 缺点：需要重构现有语音面板，风险和改动面较大。

## 中策：新增通用语音输入组件

新增 `VoiceConversationInput.vue`，内部封装 ASR Worker 状态、麦克风监听和识别结果发送；通过 slot 接收工具栏内容，由 `ChatComposer` 在 ASR 开启时切换组件。

- 优点：满足当前需求，改动集中，不影响现有文本输入和 ThreadView 布局。
- 缺点：和旧 `VoicePanel` 暂时存在部分 ASR 采集逻辑重复。

## 下策：在 ChatComposer 内直接写语音模式 UI

直接在 `ChatComposer.vue` 内通过 `v-if` 写语音模式布局。

- 优点：最快。
- 缺点：不通用，组件会继续膨胀，后续复用成本高。

## 选定方案

选择中策。原因是本次需求明确要求“通用组件”，同时希望只改对话框区域；新增独立组件能控制影响范围，并为后续抽取 composable 留好边界。
