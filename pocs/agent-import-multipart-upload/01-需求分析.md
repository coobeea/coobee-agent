# 智能体导入接口 multipart 直传改造 - 需求分析

> 创建时间：2026-04-30

## 需求背景

将 VAT 智能体（vat_tax_assistant）转换为 coobee-agent 标准导入包后，得到一个约 32MB 的 ZIP（未压缩约 64MB，内含 25900+ 个 skill 文件）。在 AgentView 导入该包时，前端控制台直接抛出：

```
[AgentView] Import error: RangeError: Maximum call stack size exceeded
```

后端 `agent-import-export.log` 和 `gateway-http-agents.log` 均无任何 `/agents/import` 命中记录，说明请求根本没到达后端。

进一步定位发现两层问题：

1. 前端 `importAgent()` 使用 `String.fromCharCode(...uint8Array)` 做 base64 编码。对于 32MB 文件会把三千多万个字节展开成函数参数，V8 参数数量上限被瞬间击穿。
2. 即便前端编码成功，后端 `koa-bodyparser` 默认 `jsonLimit: '1mb'`，而 base64 会让 32MB 膨胀到约 42.6MB，也会被直接 413 拒掉。

两个缺陷都来源于同一个架构选择：**"把二进制文件塞进 JSON body"**。这是反模式，只要包体稍大就一定会暴露。

## 核心目标

- 让任意体量（≤ 200MB）的智能体导入包都能一次性导入成功。
- 消除"base64 膨胀 + JSON 体积限制"这条反模式链路，为未来其他大文件上传接口（如附件、知识库资源）建立标准做法。
- 改动只影响 `/gateway/agents/import` 这一个接口的传输层，不动 `AgentImportExport` 领域逻辑。

## 约束条件

- 不改动 `AgentImportExport.importAgent(zipPath)` 内部实现，它接收磁盘路径不变。
- `ApiResponse<ImportResult>` 契约不变，前端 UI 层（AgentView）零感知。
- 不影响其它走 JSON body 的路由（ChatRoutes、ConfigRoutes、FileRoutes、ThreadRoutes、ThreadlessRoutes 等）。
- 前端继续走 `fetch`，不引入新的 HTTP 客户端栈。

## 涉及范围

- 模块：Gateway HTTP 路由层、前端 agents API 封装
- 文件：
  - 后端：`src/main/routes/AgentRoutes.ts`（import 路由改造）
  - 后端：`src/main/common/gateway/GatewayServer.ts`（评估是否调整 bodyParser 配置）
  - 前端：`src/renderer/src/api/agents.ts`（`importAgent` 实现重写）
  - 类型：新增 `src/main/types/koa-augment.d.ts`（抵消 `@koa/multer` 全局类型副作用）
- 接口：`POST /gateway/agents/import`（Content-Type 从 `application/json` 改为 `multipart/form-data`）
- 依赖：新增运行时依赖 `@koa/multer`、`multer`，新增 devDependencies `@types/koa__multer`、`@types/multer`
