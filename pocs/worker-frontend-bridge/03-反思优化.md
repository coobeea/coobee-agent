# Worker 前端对接方式 - 反思优化

> 创建时间：2026-04-29

## 边界情况检查

1. Worker 未注册：
   - `worker.list` 返回空列表，状态栏显示“无服务”。
   - 设置页应提示没有可用内置服务。

2. Worker 已注册但未启动：
   - 前端只能展示状态和发起启动。
   - 业务 client 不能直接连接端口，应先判断 `worker.status === "ready"`。

3. Worker 启动中：
   - ASR/TTS/OCR client 不能抢先连接。
   - UI 应显示 initializing / starting，而不是报错。

4. Worker ready 后端口变化：
   - client 应从 store 读取最新端口。
   - 已建立连接在 Worker restart 后需要关闭并重连。

5. Gateway 重连：
   - `workerStore` 应在 Gateway reconnect 后自动 `worker.list`。
   - 当前 store 已能主动 `requestWorkers`，后续可补 `gateway.onConnect` 自动刷新。

6. Worker 崩溃：
   - `WorkerManager` 推送 `worker:status`。
   - client 需要断开业务 WebSocket，UI 状态同步为 error/stopped。

## 安全隐患评估

### 本地 Electron 场景

默认 `Env.main.serverHost = 127.0.0.1`，Worker 也使用同一个 host 启动。此时前端直连 Worker 端口是可接受的，因为 Electron renderer 和 Worker 都在本机。

### 局域网 Web 场景

风险明显更高：

- 前端 `configManager.getHost()` 在外部浏览器访问时会使用 `location.hostname`。
- 但 Worker 如果绑定 `127.0.0.1`，外部浏览器无法连接 `ws://局域网IP:{workerPort}`。
- 如果把 Worker 绑定到 `0.0.0.0`，则 ASR/TTS/OCR 端口会暴露到局域网。
- Worker 当前没有独立鉴权机制，暴露后其他设备也可能调用。

结论：

- 中策适合本地 Electron 优先。
- 如果产品明确要求局域网浏览器也完整使用 Worker 能力，应增加 Gateway 代理或 Worker token。

## 对现有功能的影响

### 正向影响

- 状态栏和设置页可以复用同一份 Worker store。
- VoicePanel 不再因为缺少 `@/stores/worker` 直接类型失败。
- Worker 配置、模型切换、启停路径更清楚。

### 潜在影响

- 当前 `VoicePanel.vue` 仍直接实现 ASR/TTS WebSocket 逻辑，后续应迁到 client。
- 旧项目中 `useTtsPlayback.ts` 尚未迁到当前项目，TTS 的流式朗读复用能力还不完整。
- OCR Worker 虽已迁移并有端点，但当前前端还没有统一消费入口。

## 性能评估

- 管理通道数据量很小，走 Gateway 没问题。
- ASR PCM 是高频二进制流，直连 Worker 延迟更低。
- TTS 音频结果通常为 base64 JSON，直连可以减少主进程转发压力。
- OCR 图片 base64 数据可能较大，直连可以减少 Gateway 负担，但也更需要错误处理和大小限制。

## 可维护性评估

当前最需要避免的是“每个组件都自己拼 Worker URL”。如果继续这样做，后续任何端点变化、host 变化、安全策略变化都会分散修改。

建议收敛到：

```text
业务组件
  ↓
useAsrWorker / useTtsWorker / useOcrWorker
  ↓
workerStore 获取状态和端口
  ↓
Worker 自己的 HTTP/WebSocket 服务
```

这样保留直连性能，也保留未来切到 Gateway 代理的可能性。

## 最终优化建议

1. 短期采用中策，不做 Gateway 大流量代理。
2. 新增统一前端 Worker client，不再让业务组件散落拼 URL。
3. OCR client 和 TTS playback composable 要补齐。
4. 明确 LAN/Web 访问是独立能力，如果要支持，应做 Gateway 代理或 token 鉴权。
5. 在 `worker.json` 或共享类型里沉淀端点契约，避免前端硬编码每个 Worker 的协议。
