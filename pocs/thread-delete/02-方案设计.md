# 会话删除 - 方案设计

> 创建时间：2026-04-29

## 上策：删除策略可配置

- **核心思路**：删除时支持只删会话记录、归档、同时清理工作区三种策略。
- **优点**：长期最完整，能覆盖更多数据治理场景。
- **缺点**：需要设计更多 UI 和数据恢复策略，第一版成本偏高。

## 中策：删除会话记录，保留工作区

- **核心思路**：复用 `ThreadStore.delete()` 物理删除 Thread JSON；前端从列表移除；当前页被删除则回主页。
- **优点**：实现小，符合当前 `ThreadStore` 已有能力；不误删用户文件。
- **缺点**：工作区目录会保留，后续如果需要彻底清理要再加入口。

## 下策：只在前端隐藏

- **核心思路**：前端从列表移除，不改后端数据。
- **优点**：最快。
- **缺点**：刷新后会恢复，不是真删除。

## 选定方案

选择中策。第一版先解决会话列表清理需求，同时保留工作区文件，避免误删用户资产。
