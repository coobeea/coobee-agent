## 需求确认

最终确认目标是：

> 参考旧项目 `/Users/lifeng/git/git_agents/coobee-ai/workers` 的 Worker 机制，为 `coobee-agent` 选择一套更合理的 Worker 目录、分发、运行和配置方案。

当前选定方案：

```text
resources/workers/{name}             # 开发态内置 Worker 源码
process.resourcesPath/workers/{name} # 生产态内置 Worker 模板
{runtimeHome}/workers/{name}         # 运行产物目录
```

## 旧目录本质

旧目录：

```text
/Users/lifeng/git/git_agents/coobee-ai/workers
```

本质上是一个**开发态 Worker 工作区**，不是纯资源目录。

它同时承担了三类职责：

1. **源码目录**
   - `worker.json`
   - `server.py`
   - `requirements.txt`
   - `models.json`
   - 测试与 README

2. **运行目录**
   - Worker 进程以该目录为 `cwd`
   - 代码通过相对路径导入本地模块

3. **运行产物容器**
   - `venv/`
   - `__pycache__/`
   - `local_config.json`

旧目录 `.gitignore` 已经忽略：

```text
*/venv/
__pycache__/
*.pyc
*.pyo
```

这说明旧设计允许运行产物放在 Worker 目录内，但不进入 Git。

## coobee-agent 当前状态

`coobee-agent` 已经有 WorkerManager：

- `src/main/common/worker/WorkerManager.ts`
- `src/main/common/worker/types.ts`
- `src/main/config/workers.ts`
- `src/main/lifecycle/ReadyWorkerRegistrationHook.ts`

当前代码倾向：

- 开发态扫描 `<项目根>/resources/workers`
- 生产态扫描 `process.resourcesPath/workers`
- venv 由 Worker Runtime 路径统一解析

也就是说，`coobee-agent` 当前已经切换到 `resources/workers` 作为内置源码目录。

## 核心问题

这次不是“要不要放 resources”这么简单，而是要拆开四个概念：

| 概念         | 说明                                   |
| ------------ | -------------------------------------- |
| 源码源       | Git 中维护 Worker 源码的位置           |
| 应用内置资源 | 打包后随应用分发的 Worker 默认版本     |
| 用户运行副本 | 用户可改配置、可启停、可升级覆盖的目录 |
| 运行产物     | venv、模型缓存、日志、业务数据         |

旧项目把这四类东西大多混在 `workers/{name}`。新项目应当拆开。

同时，开发环境和生产环境不应使用两套运行模型。开发态也应该把运行数据写入统一 Runtime 目录，例如：

```text
{runtimeHome}/workers/{name}/venv
{runtimeHome}/workers/{name}/data
{runtimeHome}/workers/{name}/cache
{runtimeHome}/models
```

这样可以提前发现生产环境只读资源、可写目录、路径权限等问题。

## 目标

1. 找到适合 `coobee-agent` 的 Worker 源码目录。
2. 找到适合应用打包分发的 Worker 资源目录。
3. 找到适合运行时写入的用户目录。
4. 保证开发环境和生产环境目录形状一致。
5. 避免把 `venv`、模型缓存、业务数据放进 Git 或应用资源目录。
6. 尽量复用现有 WorkerManager，避免为了迁移引入过重架构。

## 非目标

- 本 POC 不立即迁移所有 Worker 源码。
- 本 POC 不立即重构 ASR/TTS/OCR/Brain/Tavern 的服务框架。
- 本 POC 不设计完整 Worker 市场。
- 本 POC 不把模型文件打进应用包。
