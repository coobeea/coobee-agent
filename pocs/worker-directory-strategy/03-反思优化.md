# Worker 目录策略选型 - 反思优化

> 创建时间：2026-04-29
> 最近更新：2026-04-29

## 已修正的判断

前一版担心 `resources/workers` 会被运行产物污染，所以倾向项目根 `workers/`。

现在运行产物已经统一迁到 `{runtimeHome}/workers/{name}`，这个担心被解除。因此源码主目录放到 `resources/workers` 更符合当前项目的资源归口。

## 关键边界

### 1. 内置源码可以进 Git

例如：

```text
resources/workers/asr/server.py
resources/workers/asr/requirements.txt
resources/workers/asr/worker.json
```

这些是产品能力的一部分，应当可 review、可测试、可版本管理。

### 2. 运行产物不能进 Git

例如：

```text
{runtimeHome}/workers/asr/venv
{runtimeHome}/workers/asr/data
{runtimeHome}/workers/asr/cache
{runtimeHome}/workers/asr/config.json
```

这些内容和机器、用户、网络环境有关，不能作为内置源码。

### 3. 开发环境也要按生产运行模型跑

开发态和生产态使用相同目录形状：

```text
{runtimeHome}/workers/{name}/venv
{runtimeHome}/workers/{name}/data
{runtimeHome}/workers/{name}/cache
{runtimeHome}/models
```

区别只应该是 `runtimeHome` 的取值，而不是目录模型不同。

### 4. 生产态要避免 asar 执行问题

Worker 是外部 Python 进程运行的脚本，不应依赖 Python 读取 asar 内路径。

因此生产包中需要通过 `extraResources` 将 `resources/workers` 复制到：

```text
process.resourcesPath/workers
```

## 最终建议

采用三层模型：

```text
resources/workers/               # 开发态内置源码，Git 跟踪
process.resourcesPath/workers/   # 生产态内置模板，打包复制
{runtimeHome}/workers/           # 统一 Worker 运行目录
```

再配合：

```text
{runtimeHome}/models/            # 共享模型缓存
```

第二阶段再做：

- 内置模板安装到 `{runtimeHome}/workers/{name}/source`
- 用户配置覆盖
- Worker 版本迁移
