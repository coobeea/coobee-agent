# Worker 目录策略选型 - 方案设计

> 创建时间：2026-04-29
> 最近更新：2026-04-29

## 最终分层

Worker 目录按三层管理：

```text
resources/workers/{name}             # 开发态内置 Worker 源码，Git 跟踪
process.resourcesPath/workers/{name} # 生产态内置 Worker 模板，打包复制
{runtimeHome}/workers/{name}         # 运行产物目录，可写
{runtimeHome}/models                 # 共享模型缓存，可写
```

其中 `{runtimeHome}` 由配置解析：

- 开发态默认：`Env.paths.userHome`
- 生产态默认：`~/.coobee-agent`
- 调试或测试时：通过 `WORKER_RUNTIME_HOME` / `VITE_WORKER_RUNTIME_HOME` 覆盖

## 为什么源码放 `resources/workers`

现在运行产物已经不再写入源码目录，所以 `resources/workers` 作为“应用内置能力资源”更清楚：

- 和 `resources/skills`、`resources/agents`、`resources/extensions` 归口一致。
- Worker 源码是应用自带能力，不是用户运行数据。
- 开发态能直接 review 和编辑源码。
- 生产态可以通过 `extraResources` 拷贝到 `process.resourcesPath/workers`，避免 Python 进程读取 asar 内文件。

## 为什么运行产物不放 `resources/workers`

Worker 会产生与机器、用户、网络环境相关的内容：

- `venv/`
- `data/`
- `cache/`
- `logs/`
- `local_config.json`
- 下载模型和缓存

这些不能进入 Git，也不能写入应用内置资源目录。统一写入：

```text
{runtimeHome}/workers/{name}/venv
{runtimeHome}/workers/{name}/data
{runtimeHome}/workers/{name}/cache
{runtimeHome}/workers/{name}/config.json
```

模型目录保持共享：

```text
{runtimeHome}/models
```

## WorkerManager 运行流程

开发态：

```text
读源码：resources/workers/{name}
写运行：{runtimeHome}/workers/{name}
```

生产态：

```text
读源码：process.resourcesPath/workers/{name}
写运行：{runtimeHome}/workers/{name}
```

启动流程：

1. 扫描内置 Worker 源码目录，读取 `worker.json`。
2. 创建 `{runtimeHome}/workers/{name}`。
3. 创建或复用 `{runtimeHome}/workers/{name}/venv`。
4. 从内置源码目录读取 `requirements.txt` 并安装依赖。
5. 使用 runtime venv 的 Python 启动内置源码目录中的 `server.py`。
6. 注入 `MODEL_DIR`、`WORKER_RUNTIME_DIR`、`WORKER_DATA_DIR`、`WORKER_CACHE_DIR`、`WORKER_CONFIG_PATH`。

## 打包策略

Python 子进程不能稳定直接执行 asar 内脚本，所以生产态需要明确复制：

```yaml
extraResources:
  - from: resources/workers
    to: workers
    filter:
      - '**/*'
      - '!**/venv/**'
      - '!**/data/**'
      - '!**/cache/**'
      - '!**/logs/**'
      - '!**/__pycache__/**'
      - '!**/*.pyc'
      - '!**/*.pyo'
      - '!**/local_config.json'
```

## 后续用户运行副本

第二阶段如果需要支持用户修改内置 Worker，可以再引入：

```text
{runtimeHome}/workers/{name}/source
```

但这不是当前迁移的前置条件。当前阶段先保持：

- 内置源码只读。
- 用户运行产物外置。
- 用户配置后续再设计覆盖规则。
