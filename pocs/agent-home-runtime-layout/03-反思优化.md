# Agent Home 运行目录重定义 - 反思优化

## 边界情况检查

1. Streaming writer 当前只拿到 `sessionId`，不一定直接知道 `agentId`。
   - 新模型要求通过 ThreadStore 根据 sessionId/threadId 查到 Agent，再计算 `.home/agents/{agentId}/sessions/{threadId}`。
   - 如果无法解析 Agent，不再 fallback 到 `.home/workspaces/{threadId}`，应直接报错。

2. `workspacePath` 字段已经被前端和事件使用。
   - 新模型下需要明确它到底表示“会话产物目录”还是“工具工作目录”。
   - 建议内部新增更明确的概念：`sessionPath` 和 `agentWorkspacePath`，旧字段不作为长期兼容方案。

3. `metadata.dataDirectory` 的旧语义需要废弃。
   - 新默认业务工作区固定为 `.home/agents/{agentId}/workspace`。
   - 旧字段不再参与默认路径解析，避免外部数据目录继续分叉。
   - 如后续需要自定义工作区，应作为新功能单独设计。

4. 旧 `.home/workspaces/{threadId}` 可能已有历史文件。
   - 不做运行期兼容读取。
   - 如果需要保留历史，应在实施前或启动迁移阶段一次性搬到新 session 目录。

5. PiMono/OpenAI runtime 对 `sessionDir` 的理解不同。
   - 需要验证 `builder.sessionDir()` 传入新 session root 后，OpenAI、PiMono 都不会重复拼错目录。

## 安全隐患评估

- 工具 cwd 不应设为 `.home/agents/{agentId}` 根目录，否则可能误写或误删人格文件、技能包和会话索引。
- `exec` 工具仍是高风险工具，路径迁移不能扩大可写边界到整个 `.home/agents/{agentId}`。
- path-only sandbox 的 `workspaceRoot` 应该是 `.home/agents/{agentId}/workspace`，不是 Agent Home 根。
- 如需允许读取 Skill 脚本，读取路径应通过 SkillManager 暴露；写入仍应落到 Agent workspace。

## 对现有功能的影响

- 会话列表：`ThreadStore` 返回的路径字段需要按新语义调整，旧 UI 依赖应同步修改。
- 历史读取：`ThreadRoutes` 需要从新 session 目录读取 `history.jsonl`。
- 实时写入：`EventWriter`、`HistoryWriter` 不能继续固定写 `.home/workspaces/{sessionId}`。
- 文件上传/复制：如果 FileRoutes 仍限制在全局 `workspacesDir`，需要调整到 Agent workspace 或 session path。
- Runtime prompt：`runtime_environment` 需要说明 `agent_home`、`workspace/data_directory`、`session_dir`、`skills` 的区别。

## 性能和可维护性评估

- 目录解析应集中，避免每个模块重复 `path.join(agentHome, ...)`。
- Streaming writer 高频写入，不应每条事件都重新读 Thread 文件；可以按 sessionId 做路径缓存。
- 一次性迁移逻辑应幂等，重复启动不会重复搬迁或覆盖文件。
- 主流程不保留新旧目录兼容读取，避免永久保留两套路由。

## 优化建议

1. 第一阶段先引入轻量路径对象，哪怕不单独成服务，也要让 Resolver 返回完整路径：

```ts
agentHomePath
agentWorkspacePath
dataDirectory
sessionDir
agentSkillsPath
```

2. Runtime prompt 中用统一命名：

```text
agent_home: Agent 身份、人格、记忆、技能、配置
workspace/data_directory: 工具 cwd 和业务数据落点
session_dir: 当前会话运行产物
skills: Agent 私有技能包
```

3. 第一阶段不新增 `skill_exec` 工具。

等发现现有 `exec` 在执行 Skill 脚本时仍容易出错，再考虑增加专门工具。专门工具的价值应是“脚本解析、参数审计、固定 cwd、结果结构化”，而不是为了目录迁移而提前新增。

## 最终建议

先按中策实施：

- Agent Home 根目录保留为系统/身份根，不作为工具 cwd。
- Agent workspace 作为工具 cwd 和业务数据目录。
- Agent sessions 作为会话运行产物目录。
- 旧路径只做一次性迁移或清理，不做运行期兼容读取。
- 不新增 `skill_exec` 工具。
