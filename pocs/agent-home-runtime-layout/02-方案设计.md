# Agent Home 运行目录重定义 - 方案设计

## 上策：引入统一 AgentRuntimeLayout 服务

### 核心思路

新增一个统一的运行目录解析服务，例如 `AgentRuntimeLayoutResolver`，所有模块都通过它获取路径：

```ts
{
  agentHomePath,
  agentWorkspacePath,
  dataDirectory,
  sessionRoot,
  sessionHistoryFile,
  sessionEventsFile,
  sessionContextFile,
  agentSkillsPath
}
```

该服务内部负责：

- 计算新目录。
- 创建必要目录。
- 可选执行一次性旧目录迁移。
- 禁止调用方自行拼 `.home/workspaces/{threadId}` 或 `.home/data/{agentId}`。
- 发现无法解析的新路径时直接抛错，不做旧路径 fallback。

### 改动范围和影响

- 改动范围最大，需要替换 ThreadStore、AgentContextResolver、EnvInjector、EventWriter、HistoryWriter、ThreadRoutes、FileRoutes 中的路径拼装。
- 可以顺便清理 `workspacePath` 字段语义，把会话路径和业务 workspace 明确拆开。
- 测试覆盖面需要较大。

### 优点

- 架构边界最清楚，后续不容易再次出现路径漂移。
- 目录创建和一次性迁移集中管理。
- 更容易支持后续 Agent 导入导出、打包、备份。

### 缺点

- 实施成本最高。
- 需要协调较多旧测试和旧字段语义调整。

## 中策：扩展现有 Resolver，先完成目录语义迁移

### 核心思路

在现有 `AgentContextResolver` 和 `AgentEnvInjector` 基础上完成第一阶段迁移：

- 默认 `dataDirectory` 改为 `.home/agents/{agentId}/workspace`。
- `prepared.workspace` / 工具 `cwd` 改为 Agent workspace。
- `prepared.sessionDir` 改为 `.home/agents/{agentId}/sessions/{threadId}`。
- Thread 历史、事件、上下文读写迁到新的 session 目录。
- 旧 `.home/workspaces/{threadId}` 和 `.home/data/{agentId}` 只允许一次性迁移或清理，不做运行期兼容读取。
- 旧 `metadata.dataDirectory` 自定义字段不再参与默认路径决策，避免继续制造外部数据目录分叉。

为了避免继续分散拼路径，可以增加一个轻量 helper，例如：

```ts
resolveAgentRuntimeLayout(agentId, sessionId)
```

但不强制做完整服务拆分。

### 改动范围和影响

- 主要改当前已经收敛的 Resolver、EnvInjector、ThreadStore、Streaming writers、ThreadRoutes。
- 梳理现有字段，必要时新增 `sessionPath`、`agentWorkspacePath`，不通过旧 `workspacePath` 做长期兼容。
- 不新增 `skill_exec` 工具。

### 优点

- 与当前代码结构最贴近，实施成本适中。
- 可以快速验证新目录模型是否符合使用习惯。
- 风险可控，便于分阶段回滚。

### 缺点

- 如果不把路径 helper 做好，后续仍可能出现局部手写路径。
- 需要一次性调整旧字段语义，短期改动面会比兼容方案更集中。

## 下策：直接切换新路径，不做迁移工具

### 核心思路

直接把运行路径切到新模型：

- 业务数据目录改为 `.home/agents/{agentId}/workspace`。
- 工具 cwd 指向 `.home/agents/{agentId}/workspace`。
- 会话产物写入 `.home/agents/{agentId}/sessions/{threadId}`。
- 不提供旧数据迁移工具，也不做旧路径读取 fallback。

### 改动范围和影响

- 改动集中在路径默认值和写入位置。
- 旧数据不会自动搬迁，历史会话可能不可见或需要手工处理。

### 优点

- 最快实现。
- 主流程最干净，没有兼容分支。

### 缺点

- 对已有数据最不友好。
- 缺少可审计的一次性迁移过程。
- 旧目录清理需要人工处理。

## 推荐方案

推荐采用中策。

原因：

- 当前已经有 `AgentContextResolver`、`AgentEnvInjector`、Skill 搜索路径管理等基础，不需要一开始就引入大服务。
- 用户当前最关注的是目录语义和执行 cwd，而不是先设计一个新的工具系统。
- 第一版直接让新会话按新目录写入，旧数据只做一次性迁移或清理；验证稳定后，再考虑是否抽出完整 `AgentRuntimeLayoutResolver`。
- 不做运行期兼容是本 POC 的明确约束，旧路径不再作为读取 fallback。

## 选定方案

待用户审核确认。

当前建议选定：中策，先完成目录语义迁移，不新增 `skill_exec` 工具，不做旧路径运行期兼容。
