# workspace/project 命名收敛 V1 · 方案设计

## 方案结论

采用“收窄版重命名”：

- **用户和 LLM 可见层**统一为 `project`。
- **物理业务目录**统一为 `project/`。
- **会话临时 Skill 来源**改为 `session`。
- **内部通用执行上下文**暂时保留 `workspaceRoot` 等术语，避免第一版扩大到 sandbox、tool API、runtime builder 的系统性重构。

这不是放弃命名一致性，而是把命名一致性先落在最关键、最容易产生误解的边界上。

## 命名映射

V1 必改：

- `.home/agents/{agentId}/workspace/` → `.home/agents/{agentId}/project/`
- `agentWorkspacePath` → `agentProjectPath`
- `workspacePath`（Thread 对外业务目录字段）→ 新增/改为 `projectPath`
- `<workspace_context>` → `<project_context>`
- `workspace_context` block id → `project_context`
- `COOBEE_PROJECT` 新增为推荐变量
- `SkillSearchPathKind: 'workspace'` → `'session'`
- UI 文案“工作区/任务工作目录” → “项目/业务项目”

V1 暂不机械替换：

- `workspaceRoot`
- `workspace` 局部变量，如果它只是 sandbox/tool 的执行根目录
- `WorkspaceEvents`
- `/workspace/*` HTTP 路由，除非当前实际存在并且只服务这一个业务目录
- 历史文档、历史 POC、日志快照里的 workspace 字样

## 改造分层

### 第 1 层：运行目录布局

文件：

- `src/main/agent/context/AgentRuntimeLayout.ts`
- `src/main/agent/context/AgentContextResolver.ts`
- `src/main/agent/threads/ThreadStore.ts`
- `src/shared/events/thread.ts`

动作：

- `agentProjectPath = path.join(agentHomePath, 'project')`。
- `dataDirectory = agentProjectPath`。
- `ThreadIndexEntry` 增加 `projectPath`。
- 如需短期保留 `workspacePath`，仅作为 deprecated alias，值等于 `projectPath`，不在 UI 和 prompt 中展示。

### 第 2 层：安全迁移

新增迁移能力：

- 扫描 `.home/agents/*/workspace/`。
- 迁移到 `.home/agents/*/project/`。
- 预扫描阶段发现目标已存在且源目录非空时，默认中止并记录清楚，不静默覆盖。
- `rename` 失败且错误为跨设备移动时，使用 `cp` + 校验 + 删除源。
- 成功后写入 `.home/.migration-agent-project-v1.json`，记录版本、时间和迁移明细。

迁移入口：

- 放到应用 ready 早期 hook，必须早于 Agent system / Worker / Thread 恢复。
- 如果迁移失败，不进入主界面，应给出清晰错误日志。

### 第 3 层：Runtime Prompt 和环境变量

文件：

- `src/main/agent/AgentEnv.ts`
- `src/main/agent/AgentEnvInjector.ts`
- `src/main/agent/prompt/PromptAssemblyService.ts`

动作：

- `<runtime_environment>` 输出：
  - `project: /.../agents/{agentId}/project`
  - `data_directory: /.../agents/{agentId}/project`
  - `session_dir: /.../agents/{agentId}/sessions/{sessionId}`
- 新增 `COOBEE_PROJECT`。
- `COOBEE_DATA_DIRECTORY` 继续等于 project。
- `COOBEE_WORKSPACE` 是否保留由实现阶段确认；如果保留，只作为兼容脚本的隐藏 alias，不在 prompt 中推荐。
- `PromptAssemblyService` 读取 project 根目录 Markdown，输出 `<project_context>`。

### 第 4 层：Skill 来源命名

文件：

- `src/main/agent/skills/SkillManager.ts`
- `src/main/agent/skills/__tests__/*`
- 相关 Skill 文档

动作：

- `SkillSearchPathKind = 'system' | 'extension' | 'marketplace' | 'agent' | 'session'`。
- 原 `workspace` 来源 label 改成“Session skills”或“会话技能”。
- 路径可以仍在 project 下的某个临时子目录，关键是分类名不再叫 workspace。

### 第 5 层：前端展示

文件：

- `src/renderer/src/components/agent/ProjectPanel.vue`
- `src/renderer/src/views/ThreadView.vue`
- `src/renderer/src/views/ThreadViewDual.vue`
- `src/renderer/src/stores/threads.ts`
- `src/renderer/src/composables/useWorkspaceWatcher.ts`

动作：

- UI 展示使用“项目”或“业务项目”。
- 前端优先消费 `projectPath`。
- `useWorkspaceWatcher` 是否改名为 `useProjectWatcher` 本轮可以做，但不要求全量事件系统改名。

### 第 6 层：文档最小更新

只更新会影响新模型行为的文档：

- `resources/skills/asr/SKILL.md`
- `resources/skills/tts/SKILL.md`
- `resources/skills/skill-creator/SKILL.md`
- `resources/skills/system-config/references/self-improvement.md`
- 活跃 POC 文档

不批量改历史 reference snapshot。

## 兼容策略

- 物理目录不保留双写。
- 迁移成功后，运行时只写 `project/`。
- 对 TypeScript 字段，可以短期保留 deprecated alias，避免一次性打断前后端所有调用点。
- Prompt 和用户界面不展示 alias。

## 推荐实施方式

一个窄 PR 完成 V1：

1. Runtime layout + migration。
2. Prompt/env + project_context。
3. SkillSearchPathKind 改为 session。
4. 前端最小消费字段和文案调整。
5. 关键测试。

V1 稳定后，再决定是否进入 V2：全量 API 字段、sandbox/tool 上下文、事件枚举的深度 rename。
