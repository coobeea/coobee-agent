# TS Harness 移植 - 需求分析

> 创建时间：2026-07-28

## 需求背景

Vessel `runtime-kernel/harness`（Go）整理出了一套清晰的智能体内核模式：

- **Harness**：进程级装配根（长驻）
- **Runner**：单轮 Turn 绑定（短生命周期）
- **Orchestrator**：固定流水线 `head → prepare → stream → finish`
- **Agent**：最小推理单元（只做 `DescribeRun` + `Stream`）
- **Extension / Event / Tools / Session**：与编排解耦的横切能力

当前 coobee-agent 的执行链路分散在 `src/main/agent/`（尤其是 `AgentExecutor`）中：

- 编排、环境注入、Hook、Stream、持久化边界模糊
- `AgentExecutor` 过重（锁、env、hooks、builder、stream、cleanup 全包）
- `src/main/harness/` 目录已创建但为空，尚无边界清晰的内核模块

目标是把 vessel Go harness 的架构模式，用 **TypeScript 面向对象设计**落到 `src/main/harness/`，形成第一版可演进的内核骨架。

## 核心目标

1. 在 `src/main/harness/` 落地与 Go harness 同构的 OOP 分层骨架
2. 明确职责边界：
   - Harness = 长驻装配根
   - TurnRunner = 单轮执行入口
   - Orchestrator = 生命周期所有者
   - Agent = 可替换的推理后端（不持有 Hook/持久化）
3. 第一版优先建立**可编译、可扩展的模块边界与核心契约**，而不是一次性搬完所有 Go 实现细节
4. 设计上预留后续与现有 `agent/` / `extension/` / `events/` 的渐进迁移路径

## 约束条件

| 约束      | 说明                                                                        |
| --------- | --------------------------------------------------------------------------- |
| 语言/范式 | TypeScript，面向对象（class / interface），不用 Go 风格的包级函数堆叠       |
| 参考源    | `/Users/lifeng/git/git-coobee/vessel/runtime-kernel/harness/go`             |
| 落点目录  | `src/main/harness/`（已存在，当前为空）                                     |
| 完整性    | Go 侧本身尚未完全完整；TS 第一版允许裁剪，但核心分层必须对齐                |
| 渐进迁移  | 第一版**不强制**立刻替换 `AgentExecutor` 生产路径；可先建骨架，再逐步接线   |
| 依赖方向  | Agent 不得依赖 Extension；Hook 由 Orchestrator / Tools 调度                 |
| 现有系统  | 需兼容现有 Electron/main 进程、扩展系统、事件总线的长期演进，避免大爆炸重写 |

## 参考架构（Go SSOT）

```text
Harness.New(Options)                 // 进程长驻
  → Harness.NewRunner(RunnerConfig)  // 每 Turn
    → Runner.Run(signal)
      → Orchestrator.Run
           head → prepare → stream → finish
```

关键原则：

1. **Harness 长驻 / Runner 按轮创建** — 不把编排塞进 Agent
2. **Identity 在 NewAgent 时冻结** — 请求字段只在 Input / TurnConfig
3. **Orchestrator 拥有生命周期** — Agent 只 Describe + Stream
4. **HookRunner + Emitter 注入 RunDeps** — 不注入 Agent
5. **Spawn 走 NewRunner** — 子 Turn 与父 Turn 同构

## 已确认约束（2026-07-28）

1. **隔离实现**：只在 `src/main/harness/` 内实现，**不改动** `src/main/agent/`、`extension/`、`events/` 等任何现有代码
2. **不做接入**：不接线到 `AgentExecutor` / Thread / Route / Lifecycle；不谈迁移与替换
3. **只谈实现**：本 POC 目标是落地一套可独立编译、可独立演进的 TS OOP Harness 内核
4. **Extension / Event / Session / Tools**：均在 harness 内自建契约与实现骨架，不复用、不引用现有模块
