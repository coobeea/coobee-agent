# ASR 模型路径优化 - 方案设计

## 上策：统一 Worker 模型缓存解析层

- **核心思路**：在 WorkerManager 或共享 Python 工具中定义统一模型路径解析规则，ASR/TTS/未来模型 Worker 共同使用。
- **改动范围**：WorkerManager、ASR、TTS、Worker 配置文档。
- **优点**：长期一致性最好。
- **缺点**：涉及多个 Worker，风险和验证成本较高。

## 中策：在 ASR Worker 内补齐 ModelScope 路径解析

- **核心思路**：在 `resources/workers/asr/server.py` 中增加本地模型候选路径列表，按顺序检查用户显式路径、`MODEL_DIR/<model>`、`MODEL_DIR/models/<model>` 等路径；只有包含权重文件的目录才作为本地模型使用。
- **改动范围**：仅 ASR Worker。
- **优点**：精准解决当前问题，风险低，便于快速验证。
- **缺点**：TTS 仍保留自己的路径逻辑。

## 下策：只把默认路径改成 `MODEL_DIR/models`

- **核心思路**：把当前拼接逻辑从 `MODEL_DIR/<model>` 改成 `MODEL_DIR/models/<model>`。
- **改动范围**：ASR Worker 一处。
- **优点**：最快。
- **缺点**：不能兼容用户已配置的直接本地目录，也不能识别不完整缓存。

## 选定方案

选择 **中策**。

理由：当前用户问题集中在 ASR 本机模型启动，优先做局部修复最稳；同时加入完整性判断，能避免把 `._____temp` 仍在下载的缓存误判为可加载模型。
