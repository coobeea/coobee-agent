# ASR 延迟恢复聆听 - 方案设计

## 上策：完整回复后冷却状态机

- **核心思路**：将回复中、冷却中、聆听中、暂停中做成显式状态机。
- **优点**：长期可维护性最好。
- **缺点**：当前需求较小，改动偏重。

## 中策：在 disabled 恢复时增加 3 秒 resume timer

- **核心思路**：`disabled` 从 true 变 false 时，保持 recorder muted，启动 3 秒定时器；定时器结束后自动 unmute。用户点击麦克风时清理定时器并立即恢复。
- **优点**：改动小，符合当前组件结构。
- **缺点**：仍是局部状态，后续复杂流程可再抽状态机。

## 下策：仅延迟 unmute，不展示状态

- **核心思路**：加定时器但不改 UI。
- **优点**：最小实现。
- **缺点**：用户可能误以为麦克风卡住。

## 选定方案

选择 **中策**。

理由：既能满足 3 秒反应时间，又能通过状态说明行告诉用户稍后继续聆听。
