## 边界情况检查

### P0-1: 移除 builderProjectDir 的边界情况

#### 场景 1：workspace 为空或 undefined
**问题**：如果 `workspace` 本身为空，移除 `builderProjectDir` 后会传递空值
**现状检查**：
- `injectEnv()` 的第一步就是 `const workspace = existingWorkspace || await Env.getAgentWorkspaceDir(sessionId)`
- `Env.getAgentWorkspaceDir()` 保证返回有效路径（创建目录）
**结论**：✅ 无风险，workspace 总是有值

#### 场景 2：多项目工作空间
**问题**：如果用户期望 Agent 在一个 workspace 下操作多个项目目录，移除 projectDir 会失去这个能力
**现状检查**：
- 当前代码没有任何地方设置 `builderProjectDir`
- Builder 没有 `projectDir()` 方法
- 生产环境一直在用 `workspace` 作为唯一工作目录
**结论**：✅ 无风险，这个功能从未实现过

#### 场景 3：工具执行的 cwd 不正确
**问题**：工具执行时的 `cwd` 从 `builderProjectDir || workspace` 变为 `workspace`，可能影响工具行为
**现状检查**：
- 所有工具当前都以 `workspace` 为 cwd（因为 `builderProjectDir` 一直是 undefined）
- 沙箱策略的 `workspaceRoot` 也设置为 `workspace`
**结论**：✅ 无风险，运行时行为不变

### P0-2: 复制 Builder 配置的边界情况

#### 场景 1：Thread 没有关联的 Agent
**问题**：如果 `thread.agentId` 无效或 Agent 已删除，配置逻辑会失败
**风险**：💥 高风险，恢复路径可能崩溃
**缓解方案**：
- 增加空值检查
- 如果 Agent 不存在，记录错误日志并回退到默认配置

#### 场景 2：Agent 的 model 配置无效
**问题**：如果 `agent.model` 或 `thread.overrideModel` 是一个无效的模型 ID
**现状检查**：
- `applyProviderConfig()` 内部有容错逻辑
- 如果解析失败会 fallback 到默认模型
**结论**：✅ 已有保护

#### 场景 3：Agent 的 instructions 包含敏感信息
**问题**：恢复路径也会加载 instructions，如果其中有临时调试信息可能不合适
**现状检查**：
- 正常路径也是直接加载 `agent.instructions`
- 两条路径行为应该一致
**结论**：✅ 无额外风险

#### 场景 4：Thread 在恢复前被其他进程修改
**问题**：并发修改 Thread 元数据可能导致配置不一致
**现状检查**：
- 当前没有锁机制保护 Thread 元数据
- 这是一个已存在的问题，不是本次修复引入的
**结论**：⚠️ 已存在的并发问题，不在本次修复范围

- ✅ 无新增风险

## 优化调整

基于以上审查，对方案进行以下调整：

### P0-1 优化

**增加防御性代码**：
```typescript
// AgentEnvInjector.ts:211
// 注释：当前不区分 projectDir 和 workspace，统一使用 workspace
// 如果未来需要支持多项目目录，应在 Builder 中增加 projectDir() 方法
const effectiveCwd = workspace;
if (!effectiveCwd) {
  throw new Error('[EnvInjector] workspace is undefined, cannot build tool execution context');
}
```

**理由**：虽然 workspace 不可能为空，但增加断言让代码更健壮

### P0-2 优化

**增加错误处理**：
```typescript
// ThreadWaker.ts
try {
  const threadStore = await ThreadStore.getInstance();
  const thread = await threadStore.get(threadId);
  if (!thread) {
    log.error(`[ThreadWaker] Thread ${threadId} not found`);
    return;
  }

  const agentStore = await AgentStore.getInstance();
  const agent = await agentStore.get(thread.agentId);
  if (!agent) {
    log.error(`[ThreadWaker] Agent ${thread.agentId} not found for thread ${threadId}`);
    return;
  }

  const builder = agentExecutor.piMono().sessionMode('file').name(agent.id);
  
  // ... 其余配置逻辑
} catch (error) {
  log.error(`[ThreadWaker] Failed to build execution context for ${threadId}:`, error);
  return;
}
```

**理由**：防止 Thread 或 Agent 不存在时崩溃

**增加日志输出**：
```typescript
log.info(`[ThreadWaker] Resuming thread with config:`, {
  threadId,
  agentId: agent.id,
  model: thread.overrideModel || agent.model,
  hasInstructions: !!agent.instructions
});
```

**理由**：便于调试和问题排查
