# Agent Executor P0 问题修复 - 需求分析

> 创建时间：2026-04-22

## 需求背景

在 `agent-module-review.md` 中识别出两个 P0 级别的问题，直接影响系统的稳定性和正确性：

1. **P0-1 编译错误**：`AgentEnvInjector.ts` 中使用了未定义的 `builderProjectDir` 变量，导致 TypeScript 编译失败
2. **P0-2 执行不一致**：Thread 恢复路径（`ThreadWaker`）和正常执行路径（`ChatRoutes`）使用了不同的 Builder 配置逻辑，导致恢复出来的 Agent 上下文不正确

这两个问题都属于"止血"级别，需要立即修复：
- P0-1 阻塞了 CI/CD 流程（`pnpm typecheck` 失败）
- P0-2 导致用户在恢复会话时可能遇到不可预期的行为（模型、指令、Agent 身份丢失）

## 核心目标

### 目标 1：修复编译错误

**现状**：
```typescript
// src/main/agent/AgentEnvInjector.ts:211, 227
const effectiveCwd = builderProjectDir || workspace;  // ❌ builderProjectDir 未定义
```

**问题根因**：
- 代码刚经历过一次"workspace / projectDir 语义重构"，但没有收尾完成
- `builderProjectDir` 是重构过程中遗留的未清理变量

**目标**：
- 确定 `builderProjectDir` 的正确语义（是应该移除，还是应该实现）
- 修复编译错误，让 `pnpm typecheck` 通过
- 不引入新的语义混乱（workspace / projectDir / dataDirectory 概念要清晰）

### 目标 2：统一 Thread 恢复路径

**现状对比**：

| 配置项 | ChatRoutes（正常路径） | ThreadWaker（恢复路径） |
|--------|----------------------|----------------------|
| `sessionMode` | ✅ `'file'` | ❌ 未设置（默认 memory） |
| `name` | ✅ `agent.id` | ❌ 未设置 |
| `agentId` | ✅ 通过 `applyProviderConfig` | ❌ 未设置 |
| `modelOverride` | ✅ `thread.overrideModel \|\| agent.model` | ❌ 未设置 |
| `instructions` | ✅ `agent.instructions` | ❌ 未设置 |

**影响**：
- 用户恢复会话时，可能会丢失原 Agent 的配置
- 会话历史可能不持久化（因为缺少 `sessionMode('file')`）
- Agent Home、dataDirectory 等上下文可能丢失

**目标**：
- 让 `ThreadWaker.submitResumeMessage()` 和 `ChatRoutes.sendMessage()` 走相同的 Builder 配置逻辑
- 确保恢复路径和正常路径产生完全一致的执行上下文

## 约束条件

### 技术约束

1. **最小改动原则**：这是 P0 止血，不做架构重构，只修复明确的错误
2. **向后兼容**：不能破坏现有的正常执行路径
3. **测试覆盖**：修复后需要能通过现有测试（如果有的话）

### 时间约束

- P0 级别问题，应在 1-2 天内完成
- 优先修复 P0-1（编译错误），再修复 P0-2（执行不一致）

### 代码约束

- 不依赖 P1 级别的重构（如 `ThreadExecutionFactory`）
- 不引入新的依赖或抽象层
- 保持代码风格与现有模块一致

## 涉及范围

### 模块

- `src/main/agent/AgentEnvInjector.ts` — 环境注入器（P0-1 直接涉及）
- `src/main/agent/threads/ThreadWaker.ts` — Thread 恢复逻辑（P0-2 直接涉及）
- `src/main/routes/ChatRoutes.ts` — 正常执行路径（P0-2 参考实现）
- `src/main/agent/AgentExecutor.ts` — 执行器（可能需要微调）

### 文件

**P0-1 涉及**：
- `src/main/agent/AgentEnvInjector.ts`（第 211、227 行）

**P0-2 涉及**：
- `src/main/agent/threads/ThreadWaker.ts`（第 166-167 行）
- `src/main/routes/ChatRoutes.ts`（第 170-181 行，作为参考实现）

### 接口

**不涉及公开 API 变更**：
- `agentExecutor.submit()` 接口保持不变
- `agentExecutor.piMono()` 返回的 Builder 接口保持不变
- Thread / Agent 的数据模型保持不变

**内部接口可能微调**：
- `injectEnv()` 的实现细节
- Builder 配置链的调用顺序

## 非目标

以下内容**不在本次修复范围内**（属于 P1/P2 级别的优化）：

1. 不做 `ThreadExecutionFactory` 抽象（这是 P1 级别的重构）
2. 不重新定义 workspace / projectDir / dataDirectory 的语义（这需要更大范围的讨论）
3. 不清理 `AgentEnvInjector` 的过度职责（这是 P0-1 的遗留问题描述，但不是本次修复目标）
4. 不统一两套 Runtime 的行为差异（这是 P1-3 的范围）

## 风险评估

### P0-1 风险

**低风险**：
- 如果只是移除 `builderProjectDir`，用 `workspace` 替代，影响范围小
- 当前代码已经在生产环境运行（虽然有编译错误，但可能是运行时未触发）

**潜在风险**：
- 如果 `builderProjectDir` 有实际用途（如支持多项目 workspace），移除可能影响功能

### P0-2 风险

**中等风险**：
- 修改 `ThreadWaker` 可能影响现有的恢复逻辑
- 如果某些 Thread 依赖当前的"简化配置"，可能会出现兼容性问题

**缓解措施**：
- 先写测试，再修改代码
- 保留日志输出，便于排查问题
- 可以考虑增加 feature flag，渐进式切换

## 后续改进方向

修复 P0 问题后，应该考虑的 P1 级别优化：

1. 抽取 `ThreadExecutionFactory`，避免 ChatRoutes 和 ThreadWaker 各写一套配置逻辑
2. 明确 workspace / projectDir / dataDirectory 的语义差异
3. 把 `AgentEnvInjector` 拆成更小的职责单元
4. 增加"恢复路径"的集成测试覆盖

这些优化不在本次 P0 修复范围内，但应该记录在技术债务清单中。
