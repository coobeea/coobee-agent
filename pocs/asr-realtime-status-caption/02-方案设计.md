# ASR 实时状态字幕 - 方案设计

## 上策：完整实时字幕协议

- **核心思路**：定义独立 ASR streaming protocol，包括音频接收、语音活动、识别中、临时识别、最终确认、错误等消息类型，并做前后端统一类型。
- **优点**：长期协议最清晰。
- **缺点**：改动范围较大，当前需求不需要完整协议重构。

## 中策：新增轻量 `asr_status` 状态消息

- **核心思路**：在服务端现有 WebSocket JSON 中增加 `asr_status` 字段，例如 `speech_start`、`speech_active`、`recognizing`、`recognized`。前端 composable 增加 `onStatus` 回调，组件展示一行状态字幕。
- **优点**：不破坏现有 `partial/final`，实现小而清晰。
- **缺点**：状态协议仍是局部约定，后续若扩展更多 ASR provider 需要继续收敛。

## 下策：只在前端根据音量做假状态

- **核心思路**：不改服务端，仅根据前端音量和 partial 展示“正在听/识别中”。
- **优点**：最快。
- **缺点**：不能表达服务端是否真正收到音频和开始识别。

## 选定方案

选择 **中策**。

理由：用户明确希望服务端把识别过程实时反馈给前端，中策既能真实反映服务端处理状态，又不会破坏现有识别逻辑。
