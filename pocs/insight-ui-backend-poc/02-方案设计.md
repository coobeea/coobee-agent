# Insight UI + Backend POC - 方案设计

> 创建时间：2026-04-24
> 参考来源：`/Users/lifeng/git/git_agents/coobee-ai/docs/18-realtime-analysis/03-insight-ui-backend-overview.md`

## 上策：完整复刻参考项目架构

- **核心思路**：
  - 在当前项目中完整补齐参考项目的 Insight 能力，包括模板 CRUD、会话生命周期、触发器、分析编排、快照持久化、历史详情、配置面板、自动触发策略、轮询与后续推送扩展位。
- **改动范围**：
  - `src/main/gateway/http/insight.ts`
  - `src/main/insight/*`
  - `src/renderer/src/views/InsightView.vue`
  - `src/renderer/src/views/InsightSessionView.vue`
  - `src/renderer/src/components/insight/*`
  - `src/renderer/src/api/insight.ts`
  - 路由、侧边栏、共享类型补充、测试
- **优势**：
  - 与参考项目能力最接近，后续扩展成本最低。
  - 一次性把前后端边界与持久化模型定型。
- **劣势**：
  - 实施成本高，当前项目中还没有对应主干实现，首轮投入较大。
  - 容易把 POC 做成正式功能，交付周期拉长。

## 中策：最小闭环 POC（推荐）

- **核心思路**：
  - 基于当前项目已有 `src/shared/types/insight.ts`，优先做一套最小闭环：
    - 模板读取
    - 会话创建
    - 文本追加
    - 手动分析
    - 结果展示
    - 快照回看
  - 自动触发、暂停恢复、模板编辑、推送替代轮询放到第二阶段。
- **改动范围**：
  - 后端新增最小 `InsightOrchestrator`、`SessionStore`、`SnapshotStore`、`Analyzer`
  - 新增 Insight HTTP 路由
  - 前端新增两个页面和基础 API 封装
  - 复用现有项目的 Agent/Channel 机制完成分析调用
- **优势**：
  - 能尽快验证当前仓库是否适合承载 Insight 能力。
  - 风险可控，优先打通前后端主链路。
  - 后续可以平滑迭代到参考项目完整形态。
- **劣势**：
  - 首版自动化能力较弱，更多依赖手动分析触发。
  - 一些参考项目中的高级交互要后置。

## 下策：仅做前端静态演示 POC

- **核心思路**：
  - 只在前端搭一个静态页面，用 mock 数据演示 Insight UI，不接后端真实能力。
- **改动范围**：
  - 仅 `src/renderer/src/views/`、`src/renderer/src/components/`、少量 mock 数据
- **优势**：
  - 开发最快。
  - 可用于确认 UI 结构和交互路径。
- **劣势**：
  - 无法验证当前项目中的分析调用、存储、接口设计是否合理。
  - 后续落地时返工概率高。

## 方案对比

| 维度 | 上策 | 中策 | 下策 |
|------|------|------|------|
| 闭环完整度 | 高 | 中高 | 低 |
| 首轮成本 | 高 | 中 | 低 |
| 验证真实后端能力 | 强 | 强 | 弱 |
| 与当前项目匹配度 | 中 | 高 | 中 |
| 后续返工风险 | 低 | 中低 | 高 |

## 选定方案

选定 **中策：最小闭环 POC**。

### 选择理由

1. 当前项目已经有 Insight 共享类型，但还没有实现骨架，说明最适合先补“可跑通的最小闭环”。
2. 相比上策，中策能更快验证当前仓库的接口、存储、页面组织是否合理。
3. 相比下策，中策不是纯演示，而是能真正验证前后端边界和后续扩展路径。

## 目标架构

### 后端

- `src/main/gateway/http/insight.ts`
  - 对外暴露 Insight 路由
- `src/main/insight/InsightOrchestrator.ts`
  - 统一会话、文本追加、分析、快照落盘流程
- `src/main/insight/SessionManager.ts`
  - 会话状态管理与持久化
- `src/main/insight/SnapshotStore.ts`
  - 快照读写
- `src/main/insight/TemplateStore.ts`
  - 内置模板管理
- `src/main/insight/InsightAnalyzer.ts`
  - 调用当前项目 Agent/Channel 执行分析

### 前端

- `src/renderer/src/views/InsightView.vue`
  - 主页面，包含当前会话和历史入口
- `src/renderer/src/views/InsightSessionView.vue`
  - 历史详情页
- `src/renderer/src/components/insight/DimensionRenderer.vue`
  - 渲染维度值
- `src/renderer/src/components/insight/SnapshotTimeline.vue`
  - 快照时间线
- `src/renderer/src/api/insight.ts`
  - 统一封装 Insight 后端请求

## 实施分期建议

### Phase 1

- 建立路由、后端最小接口、内置模板、会话与快照存储

### Phase 2

- 接通分析调用、结果展示、快照详情回看

### Phase 3

- 增加自动触发、暂停恢复、历史列表、删除与异常处理
