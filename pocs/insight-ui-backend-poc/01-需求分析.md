# Insight UI + Backend POC - 需求分析

> 创建时间：2026-04-24
> 参考来源：`/Users/lifeng/git/git_agents/coobee-ai/docs/18-realtime-analysis/03-insight-ui-backend-overview.md`

## 需求背景

参考项目 `coobee-ai` 已经沉淀了一套较完整的“实时洞察（Insight）”方案，覆盖前端界面、后端编排、分析触发、快照存储、历史回看等能力。当前项目 `coobee-agent` 已有 `src/shared/types/insight.ts` 共享类型定义，但尚未形成对应的前后端实现闭环。

因此，本次需要在 **当前项目 `coobee-agent`** 下，参考外部项目文档，沉淀一套可执行的 Insight POC 方案文档，用于指导后续在本仓库内补齐实现。

## 核心目标

1. 在当前项目中规划一套 Insight 最小可行闭环，覆盖模板、会话、文本追加、分析触发、结果展示、快照回放六类能力。
2. 复用当前项目已有的共享类型定义，避免重新设计一套不兼容的数据模型。
3. 产出完整 POC 文档和可执行 TODO，供后续开发直接落地。

## 当前项目现状

### 已存在

- `src/shared/types/insight.ts`
  - 已定义 `AnalysisTemplate`
  - 已定义 `InsightSession`
  - 已定义 `AnalysisSnapshot`
  - 已定义 `AnalysisResult`
  - 已定义 `RefreshStrategy`

### 尚未落地

- `src/main` 下未见完整 Insight 编排与存储实现
- `src/main/gateway/http` 下未见 Insight HTTP 路由
- `src/renderer/src` 下未见 Insight 页面、组件、API 封装

这说明当前项目适合先做“参考现有成熟设计，补齐当前仓库最小闭环实现”的 POC。

## 约束条件

1. 本次先产出 POC 文档，不直接改业务实现。
2. 方案必须以当前项目目录结构和工程规范为准。
3. 数据结构优先沿用 `src/shared/types/insight.ts`，只在必要时补充，不推翻重做。
4. POC 应优先追求闭环可运行，而不是一次性做完整产品。

## 涉及范围

### 后端范围

- `src/main/gateway/http/`
- `src/main/insight/`
- `src/main/channels/` 或相关 Agent 调用入口
- `src/shared/types/insight.ts`

### 前端范围

- `src/renderer/src/router/`
- `src/renderer/src/views/`
- `src/renderer/src/components/`
- `src/renderer/src/api/`

## 非目标

1. 不在本阶段引入复杂的实时音频采集链路。
2. 不在本阶段实现生产级权限、审计、并发调度体系。
3. 不在本阶段做完整设计稿级别的视觉重构。
4. 不要求一次性复制参考项目全部功能细节。

## 建议的 POC 范围

### P0

- Insight 路由与页面入口
- 模板列表和会话创建
- 文本追加接口
- 手动触发分析
- 分析结果展示
- 快照列表与历史详情查看

### P1

- 自动触发策略（`manual` 之外增加 `content` / `silence`）
- 活跃会话状态查询
- 暂停 / 恢复 / 结束会话
- 历史会话列表与删除

### P2

- WebSocket 推送替代轮询
- 分析并发保护与取消
- 模板编辑能力
